- **`OptimizationSense` is removed entirely; the library is canonical minimisation** (Issue #2373, ruling 1–2 of #2375).
  - There is no replacement and no migration target. `MAXIMIZE` is not deprecated — it ceases to be expressible, and formulating a problem as a minimisation becomes the caller's job. Passing `sense=` to any constructor now raises `TypeError`.
  - **Gone:** the `OptimizationSense` enum, `_sign_for_sense`, the `sense=` keyword on `ControlCostBase.__init__` and `MFGOperatorBase.__init__`, the `sense_sign` property, and the `self.sign` / `self.sense` attributes.
  - **The acceptance artifact is byte-identity, not the suite.** `sense_sign` is `+1` for MINIMIZE, so removing a multiplication by it is bit-identical on every minimising problem — which is all of them — and every test stays green whether the arithmetic survived correctly or was mangled. Seven solver fixtures were captured before the change and re-run after: **all seven bit-identical, `max|diff| = 0.000e+00`**, with a negative control confirming the comparison detects a one-ulp perturbation. Fixture: bounds $[0,1]^d$, 9–11 points per axis, `T=0.1`, `Nt=4`, `sigma=0.1`, across 1-D and 2-D no-flux, Dirichlet, Neumann, potential and coupling cases.
  - **A ninth library file, which the planned artifact could not see.** The work order's grep — `OptimizationSense|sense_sign|_sign_for_sense` over eight named files — misses `mfgarchon/core/mfg_components.py`, which read the attribute bare as `sense=self.hamiltonian.sense`. That grep returns clean on a tree where every solve raises `AttributeError`. The byte-identity oracle caught it; the artifact would have passed. The artifact used here is widened to any `sense=` or `.sense` in library code.
  - **`BoundedControlCost` passed `sense` positionally** to its base (`super().__init__(sense, control_cost, ...)`). With the parameter gone that is a runtime `NameError`, invisible to `py_compile` and to any import-shaped check.
  - **`assert_quadratic_minimize_drift` is kept, not deleted.** Its MAXIMIZE arm goes with the concept; its non-quadratic arm stays, because `-c*grad(U)` is the wrong **form** for a regularised Moreau–Yosida cost rather than merely the wrong sign. `fp_drift_coefficient`'s quadratic branch likewise survives — only its `.sign == 1` test was dropped, having become vacuous.
  - **The network's arithmetic is deliberately untouched.** `hjb_network.py` and `extensions/topology.py` multiply by an orientation factor that is now the constant `+1`. Ruling 3/4 of #2375 rewrites those same lines, and the network's isolation step `h_control = h_total - source` changes sign with the Hamiltonian object — so flipping in two passes is exactly how a double sign flip survives with every test green. The factor is renamed off the deleted concept and the multiplications are left as written.
  - **#2341 retires as a root cause rather than a guard.** Its defect — `L1ControlCost(1e-12)` silently setting `sense=1e-12` — existed because `sense` was the first positional parameter on both owners, immediately ahead of a number. Removing the parameter removes the trap; there is nothing left to validate.
