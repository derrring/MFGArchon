- **A `functools.partial` that freezes a slot by keyword is refused rather than overridden** (Issue #2869). Every role but a boundary value and a graph node value accepted one and then passed that slot by name, which overrode the frozen value with no error: `problem.solve()` with `potential=partial(f, t=0.45)` or `source_term_hjb=partial(s, t=0.45)` solved the unfrozen function and reported convergence, 0.299 from the frozen one in `U` on a 21-node fixture. Each role now refuses it, with one check that `bind_by_name` and `adapt_ic_callable` read too, aliases such as `time` and `m_t` included. It costs a rare shape: a slot frozen by keyword on a callable bound positionally through an unnamed tail, whose frozen value stood, is refused too. A partial that freezes by position stays accepted.
- **A refused `functools.partial` that freezes by position is no longer told to reorder its function** (Issue #2861). Reordering moved the frozen value to another parameter: `partial(lambda t, x: 100*t + x, 9.0)`, written from `partial(lambda a, b: 100*b + a, 9.0)`, read 903.0 for 34.0. It is now told to write a function that passes the frozen value by keyword.
