- **A `functools.partial` that freezes a slot by keyword is refused where the library passes that slot by name** (Issue #2869). The library's call by name overrode the frozen value with no error: `problem.solve()` with `potential=partial(f, t=0.45)`, `source_term_hjb=`, `source_term_fp=` or `Model(volatility=partial(sig, t=0.45))` solved the unfrozen function and reported convergence, 0.299 from the frozen one in `U` on a 21-node fixture for the potential and 0.068 for the volatility. Each is refused now, a volatility when the `Model` or `MFGProblem` is built, through one check: a slot or an alias such as `time` or `m_t`, frozen by keyword and still a named parameter of the partial, however many levels of partial hold it. `DualHamiltonian`, `DualLagrangian` and the validators' reading of a family's method read the same check. Where the library does not pass that name the frozen value stands, and stays accepted: a slot frozen on a callable bound positionally or as a spatial one, or frozen into `**kw`, which `adapt_ic_callable` used to refuse for a time.
- **A refused `functools.partial` that freezes by position is no longer told to reorder its function** (Issue #2861). Reordering moved the frozen value to another parameter: `partial(lambda t, x: 100*t + x, 9.0)`, written from `partial(lambda a, b: 100*b + a, 9.0)`, read 903.0 for 34.0. The refusals of the binders, `bind_by_name`, `adapt_ic_callable` and `PotentialCost` now tell it to write a function that passes the frozen value by keyword.
