- **In a multi-population solve `m` is the population's own density, and every population's is `cross_density`** (Issue #2335; user ruling 2026-11-06). **Breaking.** `MultiPopulationIterator` handed each population's Hamiltonian the stack of every population's density as `m`, and the library's terms paired it with the points by position: every population read population 0's density, and the FP velocity read node densities at the faces, with no error. Now `m` is the own density at every door, at the faces at the FP velocity, and a term or a Hamiltonian method that reads every population declares `cross_density`: one row per population at the same points as `m`, and `m[np.newaxis]` where there is one population. See `CONVENTIONS.md` § *Several populations*.
  - **A body that read the stack from `m`** now gets one population's values. One that reads its shape raises; a shape-blind one, such as `np.mean(m)` meant as every population's mean, reads its own population's with no error. Declare `cross_density` instead.
  - **A density term that returns neither one value per point nor one value** is refused, saying what it was handed and what it returned, as is a per-point loop handed a density that is not one value per point.
