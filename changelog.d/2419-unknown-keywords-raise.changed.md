- **A keyword the weak-form solvers or `FixedPointIterator` do not name now raises, instead of being dropped (#2419).**
  - `WeakFormFPSolver.solve_fp_system` (and so `FPFEMSolver` and `MeshlessGalerkinFPSolver`) and `WeakFormHJBSolver.solve_hjb_system` (and so `HJBFEMSolver` and `MeshlessGalerkinHJBSolver`) ended in a `**kwargs` their bodies never read. A misspelled keyword such as `volatilty=` changed the solve by exactly 0. They now raise Python's `TypeError`. The FP side names the base interface's `show_progress`, a display switch it accepts and does not use; it does not take `progress_callback`, which it would never call.
  - `MeshlessGalerkinHJBSolver`'s `solve_hjb_system` override, which forwarded `**kwargs`, is removed. The parent now reads the solver's `_use_newton_default` when `use_newton` is not given, so the meshless constructor's `use_newton` is still the solve's default. Two side effects: its refusal of a retired volatility keyword now names `WeakFormHJBSolver.solve_hjb_system()` (as `HJBFEMSolver`'s already did), and a fourth or later positional argument now binds to the named parameter instead of raising "got multiple values".
  - `FixedPointIterator(...)` raised on a removed name such as `damping_factor` but only warned on an unknown one, and was built anyway. It now raises `TypeError` for an unknown name too.
  - The retired-volatility refusal on the weak-form solvers is now removable at v0.25.0 on schedule: the deprecation audit no longer reports it blocked by a `**kwargs`.
