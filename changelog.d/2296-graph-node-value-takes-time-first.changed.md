- **A graph node's value takes `(t, node)`, time first, and a CUSTOM node takes a rule of `(t, node, field)` as `rule=`** (#2296, #2512 row N2). **This breaks a callable written in the old order.**
  - **How the library calls them.** `NodeBC`, `set_dirichlet_nodes`, `set_source_nodes`, `apply_direct` and the factories bind a callable value once to `(t, node)`; `set_custom_bc` and `NodeBC(rule=)` bind a rule to `(t, node, field)`. Each is bound by the rule a grid boundary value is bound by (#2512 row B2), through its one owner, `callable_protocols.bind_by_name`: a function you write, a `def` or a `lambda` or a `functools.partial` of one, whose parameters are named after the slots, called by name. A value that reads no time, `lambda node: …`, is accepted and read with no time; at main it was called `(node, t)` and raised `TypeError: … takes 1 positional argument but 2 were given`.
  - **Refused by name where it is built:**
    - a value written `(node, t)`, the order `NodeBC.get_value` called it in. The refusal names `(t, node)`;
    - a callable whose parameters are not all named after the slots, such as `lambda a, b: …` or `lambda t, n: …`. At main a two-parameter callable was called `(node, t)` whatever its names, so `lambda n, s: 100*s + n` read correctly, 51.0 at node 1 and t = 0.5; name its parameters `t, node`;
    - a callable that is not a function you write (a class instance, a builtin, a ufunc, a decorated or jax-wrapped function), or whose signature cannot be read, or that has positional-only parameters. At main it was called `(node, t)`; bound by position, time first, one written in that order would have been read swapped. Wrap it, `lambda t, node: f(node, t)`;
    - a CUSTOM condition without `rule=`, or with a non-zero value: at main a scalar CUSTOM did nothing, and a `(node, t)` callable raised `TypeError: … takes 2 positional arguments but 3 were given`, naming nothing;
    - `rule=` on any other type.
  - **Refused by name where it is read:** `get_value` and `get_bc_value` on a CUSTOM condition, which has a rule and no value. At main they raised `TypeError: … missing 1 required positional argument: 't'`, naming nothing.
  - **What a value or rule returns is read as a grid boundary value's return is**, by its one reader, `types._read_constant` (#2512 row B2). `None`, a bool, a string, a non-finite number and more than one number are refused by name; a masked element reads as 0, and an array of one element as that element. At main a return was written as NumPy wrote it, in silence: `None` and a masked element as NaN, a bool as 1.0 or 0.0, a numeric string as its number, NaN and inf as themselves; on a 2-D field more than one number went into the node's column, the case the order and 2-D refusals close now; otherwise NumPy raised, naming nothing. A constant value is read as before.
  - `set_custom_bc`'s `bc_func` is the rule. At main it was documented and called as `(field, node, t)`; that order is refused now.
- **`GraphApplicator.apply`, `apply_hjb`, `apply_fp` and `apply_direct` take `t=None` for no time, not 0.0** (#2296, #2512 row N2), as the grid readers do since #2512 row B2. A constant reads as before; a value that reads no time, which main called `(node, t)`, is read with none, and into every row of a 2-D field. A value or rule that reads `t` is refused by name:
  - when no time is given. At main it was read at t = 0;
  - on a 2-D `(Nt, N)` field, which would take its value at the one time given in every row. At main it was, a CUSTOM rule's included.
