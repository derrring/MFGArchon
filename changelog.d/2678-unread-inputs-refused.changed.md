- **Breaking: an input no solve reads is refused when the problem is built** (Issue #2678). Each was accepted and changed the default solve by 0.0 in `U` and in `M`, with nothing said. Refused now: `Model(drift_field=)`; `MFGProblem(drift=)`, in both forms; `MFGProblem(constraints=)`, in both forms; `state_penalty_scale` other than 1.0 with no `state_penalty`; `suppress_warnings=True` on a geometry or a network, where no feasibility check runs (it stays on a grid the library builds itself, from `spatial_bounds=` or the default domain). The refusal of a drift names what to do instead: `solve_fp_system(drift_field=)` on `FPFDMSolver` or `FPParticleSolver`, or `FixedPointIterator(drift_field=)` over `FPFDMSolver`. Each replaces the drift the Hamiltonian gives, and reads a callable by position as `(t, x, m)` (#2864). A `Model` now needs a Hamiltonian or a Lagrangian: one with only a `drift_field` built, and then raised at `MFGProblem`.
- **Breaking: `hamiltonian=` is no longer a parameter of `MFGProblem`** (Issue #2563). Beside `components=` it was read by nothing, so the components' Hamiltonian was solved with nothing said; alone it raised, for a missing `m_initial` or a raw callable, so it built no problem. It now raises wherever it is passed, naming `Model(hamiltonian=)` and `MFGComponents(hamiltonian=)`: beside `components=` whatever its value, `None` included; alone; beside a `Model`; and on a subclass that overrides `_initialize_functions`, the one route that used to build with it, which no class in this repository takes.
- **`problem.drift_field` and `MFGProblem.get_drift_coefficient_field` are removed, and `has_state_dependent_coefficients` reads only the volatility** (Issue #2678). No solver read any of them.
