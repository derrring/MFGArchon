- **Constructing a problem no longer changes the `MFGComponents` it was given** (#2702). `MFGProblem` and `NetworkMFGProblem` hold their own copy of the components and write into that.
  - **Before,** a soft wall (`state_penalty=`) was composed into the caller's object. A second problem built from the same components, a rebuild, or a copy of `problem.components` then carried two walls, and a problem built earlier read the second wall too. A second `NetworkMFGProblem` built from the same `NetworkMFGComponents` replaced the first problem's Hamiltonian with one on its own network.
  - **The public field changes** (user ruling, 2026-11-12): after a walled construction, `problem.components.hamiltonian` is the Hamiltonian as given, and the composed one is read through `problem.hamiltonian_class`.
  - **A write into your own `MFGComponents` after the problem is built no longer reaches the problem.** Write into `problem.components` instead.
