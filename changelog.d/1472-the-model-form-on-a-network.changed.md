- **The model form declares a network MFG** (#1472, stage 2a). `MFGProblem(model=Model(hamiltonian=NetworkHamiltonian(...)), domain=<network geometry>, conditions=Conditions(...))` builds a problem the network solvers solve: the problem binds the `NetworkHamiltonian` to its geometry, one bound to another geometry included. Each network solver refused such a problem by name before.
  - **A problem on a network refuses, when it is built and by name, a Hamiltonian that is not a `NetworkHamiltonian`**, or none. One such as a `SeparableHamiltonian` built, and every network solver refused it.
  - **A `Conditions` callable on a network is read at each node, with the node as `x`, an `int`** (the user's ruling of 2026-11-28; `docs/user/CONVENTIONS.md` § *Callable signatures*). It was handed the geometry's node coordinates as a coordinate tuple. It returns one number at each node, as on a grid: a str is refused and a one-entry array read as its entry. An error it raises at a node keeps its type and names the node.
  - **A network solver refuses by name, when it is built, an input of its problem it does not read**, which it dropped: `source_term_fp=` (`FPNetworkSolver`), `source_term_hjb=` and `nonlocal_operator=` (the HJB solvers, whose `solve()` alone refused them), a `NetworkHamiltonian`'s `hamiltonian_dm_func`, and a `population_index` other than 0. A components `boundary_conditions` on a network is refused when the problem is built; the node BCs are the geometry's.
  - **`FPNetworkSolver` reads the network diffusion from the problem's volatility**, through the owner the HJB solvers read, when it is given no `diffusion_coefficient`; one that disagrees with the problem's volatility is refused by name. A `Model`'s volatility defaults to 0.1, so an explicit coefficient with a default `Model` is refused unless the volatility is set to match. A `NetworkMFGProblem` declares no volatility and keeps the default D = 0.1.
  - **A network solver reads the node BCs from the geometry when it applies them.** A node BC the geometry is given after the solver was built is applied by `FPNetworkSolver` and `NetworkPolicyIterationHJBSolver`, and refused at the solve by `NetworkHJBSolver`, which applies none. All three ignored it.
  - **`Model(coupling_cost=...)` and `Model(terminal_coupling=...)` on a network** are still refused; the refusal names `NetworkHamiltonian(node_potential_func=...)` and `Conditions(u_terminal=...)` instead.
- **`NetworkMFGProblem` builds the model form**, its node fields as its conditions (#1472, stage 2a; 2b removes the class).
  - `get_m_initial` and `get_u_terminal` return what `initial_node_density_func` and `terminal_node_value_func` give: they returned the uniform density and zeros whatever was given. A node field set on `problem.components` after the problem is built is no longer read, as on a grid. `get_problem_info` reports the initial and terminal values the problem holds.
  - It refuses, when it is built, a node density the setup refuses on every geometry: a negative entry, a non-finite one, a zero mass, and a node field that raises, named at its node. The mass reported is the given density's, and one whose node sum is not 1 is warned about; the report was the uniform density's, 1.
  - `with_model`, `with_domain` and `with_conditions` rebuild it, as an `MFGProblem`; they refused it.
  - It refuses `lagrangian_func`, which no network solver reads, and a subclass overriding `hamiltonian`, `hamiltonian_dm`, `lagrangian`, `node_potential`, `density_coupling`, `get_initial_density`, `get_terminal_value`, `terminal_value`, `get_initial_m`, `get_final_u` or `apply_boundary_conditions`, which no network solver reads through a subclass. Main read the `hamiltonian`, `get_initial_density`, `apply_boundary_conditions`, `terminal_value` and `get_terminal_value` overrides.
- **An FP solve handed no initial density starts from the problem's** (#1472). `BaseFPSolver.solve()`, and `FPFVMSolver.solve_fp_system` handed none, read `get_m_initial`. They read `get_initial_density`, which only `NetworkMFGProblem` defines, so on any other problem they raised `AttributeError`.
