- **A refusal's advice on a callable no longer reads it swapped when followed** (Issue #2861). Refusals advised rewrites that read a callable written in another order with its arguments in the wrong slots, with no error:
  - `bind_user_callable` and `bind_by_name`'s advice to name the parameters in place, `Name its parameters t, x`, which keeps the order a callable is written in. Its refusals now give one advice, to name each parameter after what it reads and order them by slot. The advice to "take exactly N positionally" is gone from a role never reordered, which still binds that way.
  - `bind_by_name`'s "Freeze it by position", which freezes the first parameter, whichever it is. A partial that freezes a slot by keyword is now told to write a function of the slots it reads, such as `lambda x: f(x=x, t=0.25)`.
  - The grid's wrap, which named only `lambda t: f(t)` for a callable that reads space. The grid now advises one wrap for a callable of time, one of space, and one of both, for a callable that cannot be called by name as for any other.
  - `adapt_ic_callable`'s refusal of a `functools.partial` that fixes time, "pass lambda x: f(0.25, x)", which read `f = 100 t + x` written `(x, t)` as 300.25 for 28.0. It now writes its lambda by keyword from the names `f` reads, and writes none where they cannot be read, or where anything but the time is frozen, or a parameter is left that it cannot say reads space. It no longer says "It takes (t, x) or (x)", false of a `PotentialCost`'s `V`.

  `refuse_methods_out_of_order` no longer says "time first" for `terminal_cost_k` and `initial_density_k`, which take no time. A raw Hamiltonian that leaves out a slot it must declare is now told which.
