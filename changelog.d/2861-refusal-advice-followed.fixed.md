- **Advice that read a callable swapped when followed is gone from the refusals below** (Issue #2861). They advised rewrites that read a callable written in another order with its arguments in the wrong slots, with no error:
  - `bind_user_callable` and `bind_by_name` said to name the parameters in place, `Name its parameters t, x`, or, for a callable with a `*args` or `**kwargs` parameter, `such as lambda t, x: ...`, which keeps the order a callable is written in. They now say to name each parameter after what it reads and order them by slot. The advice to "take exactly N positionally" is gone from a role never reordered, which still binds that way.
  - `bind_by_name` said "Freeze it by position", which freezes the first parameter, whichever it is. It named lambdas to wrap a callable in, and each read some callable wrong: `lambda t: f(t)` a function of space, `lambda t, node: f(node, t)` one with a defaulted parameter, which t landed in. It now says in words to write a function named for the slots it reads that passes each argument to the parameter that reads it, on the grid and the graph alike. For a partial that froze a slot by keyword, it adds to pass the frozen value by keyword, since a function that takes that slot as well reads the slot and loses the value.
  - `PotentialCost`'s refusal said `SeparableHamiltonian(potential=lambda t, x: ...)`, the same rename in place, which read `lambda a, b: 100*b + a` as 300.25 for 28.0. It now names the keyword with no lambda, and says to name each parameter after what it reads and order them by slot.
  - `adapt_ic_callable`'s refusal of a `functools.partial` that fixes time said "pass lambda x: f(0.25, x)", which read `f = 100 t + x` written `(x, t)` as 300.25 for 28.0. It now gives that sentence too, with one example that says what it holds for: `lambda x: f(x=x, t=T)` for an f that takes just x and t, with T the time you want.

  `adapt_ic_callable`'s refusals no longer say a callable "takes (t, x) or (x)", which is false of a `PotentialCost`'s `V`, and `refuse_methods_out_of_order` no longer says "time first" for `terminal_cost_k` and `initial_density_k`, which take no time.

  One case stays open in #2861: a `functools.partial` that freezes a slot by position, whose function is rewritten in slot order with the partial kept, moves the frozen value to another slot.
