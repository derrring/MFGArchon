  - **The source entered the Dirichlet rows.** A Dirichlet row reads m = g, a constraint rather than a balance. The source was added to every row after the Dirichlet values were set, so the solve saw the wall at g + dt·S.
    - Measured on main with `problem.solve(scheme="fdm_upwind")`, a shared exit (absorbing since #2528) and a problem-level `source_term_fp`: the exit held exactly dt·S, 0.025 for S = 1 and 0.005 for S = 0.2 at dt = 0.025, where it must hold 0.
    - An explicit DIRICHLET(0.7) on a mixed BC held 0.75 at dt = 0.05.
    - On a 1-D uniform Dirichlet the post-step overwrite reset the wall node to g, so the wall read right and the error sat in the interior.
    - The Dirichlet rows are now set after the source, as the repeated-endpoint rows already were. The source still reaches every balance row: on no-flux walls the mass grows by exactly dt·S per step, and beside a Dirichlet wall it raises every interior value.
  - **A DIRICHLET `default_bc` fall-through wall now gets its value.** The matrix gave that wall an identity row through the per-point resolver, but the RHS loop was gated on segments alone. The wall held its initial value: 0.0408 for an explicit g = 0.7, climbing 0.0908 → 0.5408 under S = 1, and the same for a shared exit. The gate (`_declares_dirichlet`) now reads every route the resolver does.
