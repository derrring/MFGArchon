- **Availability flags that could only be `True`, or only `False`, on an install that satisfies `[project].dependencies`, are deleted** (#2088). Each was set by a `try`/`except ImportError` around imports from this package. Where every imported name exists, those imports succeed even with every optional dependency made unimportable, so the flag was always `True` on such an install. Where a name does not exist, they always fail, so the flag was always `False`. The guards went too, so a missing name in the library is now Python's own `ImportError`, not a silent `False`.
  - Always `True` on such an install: `mfgarchon.NOTEBOOK_REPORTING_AVAILABLE`; in `mfgarchon.utils`, `NOTEBOOK_REPORTING_AVAILABLE`, `CLI_AVAILABLE`, `EXPERIMENT_MANAGER_AVAILABLE`, `DATA_RECORDER_AVAILABLE` and its alias `HDF5_RECORDER_AVAILABLE`; `mfgarchon.utils.AVAILABLE_MODULES`, the dict built from them; and `ProgressBarHook.tqdm_available`, which was `False` only without rich, a declared dependency. Without rich, the hook now raises at construction instead of building no bar; a default `problem.solve()` fails without rich either way.
  - Always `False`: `mfgarchon.GEOMETRY_SYSTEM_AVAILABLE`, whose block imported two names that do not exist (`BoundaryManager`, `GeometricBoundaryCondition`). The mesh names in that block were never exported at the top level, and are not now: import them from `mfgarchon.geometry`. Also `mfgarchon.utils.experiment_manager.VISUALIZATION_AVAILABLE`, whose block imported three names that do not exist. The four plot branches only it opened are deleted, and the matplotlib path, the one that always ran, stays.
  - `mfgarchon.utils.MEMORY_MANAGEMENT_AVAILABLE` and `PERFORMANCE_MONITORING_AVAILABLE` stay. They are `False` without psutil, which AGENTS.md calls optional (#2930), and their guards now catch only psutil's absence. `POLARS_AVAILABLE` stays too.
