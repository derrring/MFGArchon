- **Availability flags that could only be `True`, or only `False`, are deleted** (#2088). Each was set by a `try`/`except ImportError` around imports from this package. Where every imported name exists, the imports succeed even with every optional dependency made unimportable, so the flag was always `True`. Where a name does not exist, they always fail, so it was always `False`. The guards went too, so a missing name in the library is now Python's own `ImportError` at import, not a silent `False`.
  - Always `True`: `mfgarchon.NOTEBOOK_REPORTING_AVAILABLE`; and in `mfgarchon.utils`, `NOTEBOOK_REPORTING_AVAILABLE`, `CLI_AVAILABLE`, `EXPERIMENT_MANAGER_AVAILABLE`, `DATA_RECORDER_AVAILABLE`, its alias `HDF5_RECORDER_AVAILABLE`, `MEMORY_MANAGEMENT_AVAILABLE` and `PERFORMANCE_MONITORING_AVAILABLE`; also `mfgarchon.utils.AVAILABLE_MODULES`, the dict built from them, and `ProgressBarHook.tqdm_available`. The modules they named are always importable.
  - Always `False`: `mfgarchon.GEOMETRY_SYSTEM_AVAILABLE`, whose block imported two names that do not exist (`BoundaryManager`, `GeometricBoundaryCondition`). The mesh names in that block were never exported at the top level, and are not now: import them from `mfgarchon.geometry`. Also `mfgarchon.utils.experiment_manager.VISUALIZATION_AVAILABLE`, whose block imported three names that do not exist; the four plot branches only it opened are deleted, and the matplotlib path, the one that always ran, stays.
  - `mfgarchon.utils.POLARS_AVAILABLE` is the one availability flag left in `mfgarchon.utils`.
