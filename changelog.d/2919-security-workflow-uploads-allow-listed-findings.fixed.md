- **The security workflow uploads only allow-listed findings** (Issue #2919). Each scan job in `.github/workflows/security.yml` uploads one file, `<job>-findings.json`, which the new `.github/scripts/security_findings.py` writes. Each finding there holds only its tool, rule, file, line, commit, severity, confidence, package, version, advisory, license and status. A tool's report, stdout and stderr stay on the runner. TruffleHog runs without verification or its update check, detect-secrets without verification, Semgrep with metrics off and the `p/python` rule pack in place of `auto`, which needs metrics, Trivy without telemetry or its version check, and Safety without its optional telemetry or its upload of results.
- **The summary job reads the scan jobs' results.** `generate_security_report.py` looked for each scan report by its bare name in the working directory, while download-artifact puts each artifact in a directory named after it, so it read none, and `check_critical_issues.py` looked for five of its six inputs under names no job uploads. `security_findings.py collect` now reads `<artifact>/<job>-findings.json` for the five jobs and writes `security-findings.json` from them alone; `generate_security_report.py` and `check_critical_issues.py` read that file, so the critical-issues thresholds now apply to what the scans found.
- **The scanners' own reports.** `custom_secrets_scan.py` finds a private-key header with nothing between `BEGIN` and `PRIVATE`. `custom_security_checks.py` and `container_security_check.py` record a finding's file and line, and no longer the source or Dockerfile line there. `parse_security_results.py` is gone: its readers are in `security_findings.py`, and four files it wrote over other scripts' files of the same names are no longer overwritten.
- **One workflow runs the security scanners.** `ci.yml`'s `security-scan` job ran bandit, Safety and pip-audit on the same triggers as `security.yml` and uploaded their reports whole. It is deleted, with the `run_security_scan` input of `ci.yml`'s manual trigger, whose only reader it was.
