- **Nothing is deprecated before 1.0: every name a decorator, a warning, a refusal or a stub marked as deprecated, retired or withdrawn is deleted, with the machinery that kept them.** A removed name now raises Python's own `TypeError`, `AttributeError` or `ImportError`; it is no longer kept behind a warning, an alias, a redirect or a stub that raises. Two places refuse by name instead: the two iterators' `solve()`, which keep a `**kwargs` (below), and `MFGProblem`, which raises `ValueError` for a key of the free-form `components.parameters` dict named after one of the 14 inputs it no longer reads. `BlockIterator.solve` and `NewtonMFGSolver.solve` still accept and ignore an unknown keyword (#2922). Not removed here: names deprecated only in a docstring; `WeakFormHJBSolver.solve_hjb_system`'s three undecorated pre-v0.12 names; `mixed_bc`, `TensorProductGrid(dimension=)` and `TensorProductGrid(num_points=)`, the components= form, `MFGComponents.boundary_conditions` and `_compute_sdf_gradient`, which stay without their warning or decorator, the deprecation withdrawn; and the refusal of `NumericalScheme.GFDM`, a configuration the factory cannot build rather than a retired name. What replaces each:
  - **Coupling iterators and solvers.**
    - `damping_factor=` and `damping_factor_M=` on `BlockIterator`, `BlockJacobiIterator`, `BlockGaussSeidelIterator`, `MultiPopulationIterator`, `FixedPointSolver`, `create_network_mfg_solver` and `HJBFDMSolver`, `damping=` on `create_simple_network_solver`, and the `damping_factor`/`damping_factor_M` attributes: use `relaxation`/`relaxation_M`.
    - `PicardConfig`'s `damping_factor`, `damping_factor_M`, `damping_schedule`, `damping_schedule_M` and `adaptive_damping`, and `PicardConfig.LEGACY_FIELD_ALIASES`: use the `relaxation_*` fields.
    - `HJBFDMSolver(on_newton_failure=)`, its attribute and the `NewtonFailurePolicy` type alias: use `on_inner_failure`.
    - `NewtonMFGSolver(newton_tolerance=)`: use `solve(absolute_tolerance=)`.
    - `FixedPointIterator.solve` and `FictitiousPlayIterator.solve`: `return_tuple=` (a `SolverResult` is returned), `Niter_max=` and `max_picard_iterations=` (use `max_iterations=`), and `l2errBoundPicard=` and `picard_tolerance=` (use `tolerance=`). These five are refused by name, because both methods keep `**kwargs`.
    - `BlockIterator(adjoint_mode="transpose" | "auto")`: use `"jacobian_transpose"`.
  - **FP solvers.**
    - `FPFDMSolver.solve_fp_system(velocity_field=)`: use `drift_field=`.
    - `FPFDMSolver(advection_scheme="flux")`: use `"divergence_upwind"`.
    - `drift_field=` on the semi-Lagrangian FP solver, the network FP solver and the weak-form family (FEM, meshless): use `potential_field=`.
    - `m_initial_condition=` on the network FP solver and `m_initial=` on the weak-form family: use `M_initial=`.
    - `FPNetworkSolver(enforce_mass_conservation=)`: removed with no replacement (#1683).
    - `FPGFDMSolver`, withdrawn (#2583). `create_paired_solvers(..., NumericalScheme.GFDM)` and `problem.solve(scheme=NumericalScheme.GFDM)` still refuse with the reason until the rebuild (#2584).
  - **HJB solvers.**
    - `PenaltyHJBSolver` (#2002): use `HJBFDMSolver(constraint=ObstacleConstraint(...))`.
    - `HJBGFDMSolver`: `qp_usage_target=`, `use_new_infrastructure=`, and a `dict` for `boundary_conditions=`. Use a `BoundaryConditions`: `{"type": "dirichlet", "values": g}` is `dirichlet_bc(value=g)`, `"neumann"` is `neumann_bc(value=g)`, `"no_flux"` is `no_flux_bc()`, `"periodic"` is `periodic_bc()`; a Robin dict, which carried no coefficients, never solved, and HJB-GFDM's Robin row takes only `alpha=0, beta=1`, which is `neumann_bc(value=g)`. Two differences from what the last release did with a dict: it solved a nonzero Neumann value as 0 (#2520), and in two or more dimensions it used the diagonal normal at a corner where a `BoundaryConditions` uses the face normal (a 6.5e-3 difference on a 6×6 grid).
  - **Problems and components.**
    - `MFGProblem` no longer takes `**kwargs`. `source_term_hjb`, `source_term_fp`, `nonlocal_operator`, `state_penalty` and `state_penalty_scale` are named keyword-only parameters. `sigma=`, `gamma=`, `obstacle=`, `boundary_conditions=` and every other keyword it never read are Python `TypeError`s.
    - `problem.sigma`, `problem.volatility_field` and `problem.diffusion_field`: use `problem.volatility` and `problem.diffusion`. `problem.spatial_discretization`: use `problem.geometry.Nx` or `Nx_points`.
    - `MFGComponents(u_final=)`: use `u_terminal=`. `MFGComponents(potential_func=)`: use the Hamiltonian's `potential=`. `MFGProblem.H` and `MFGProblem.dH_dm`'s `p_values=`: use `derivs=`.
    - `Model.sigma`, `Model(sigma=)` and `MFGGridConfig(sigma=)`: use `volatility`.
    - `NetworkMFGProblem(network_geometry=)`: use `geometry=`.
    - `VariationalMFGProblem.sigma`: use `volatility`. `VariationalMFGProblem` no longer takes `**kwargs`, and its `parameters` attribute is gone.
    - `HamiltonianValues.sigma`: use `volatility`.
    - `ControlCostBase.control_cost`: use `lambda_`. `ControlCostBase.hamiltonian()`: use `evaluate()`.
  - **Never-read inputs (#2648)**, which were refused by name, are removed. The #2648 entries list them, with what to do instead.
  - **Geometry and boundary conditions.**
    - `TensorProductGrid.num_points`: use `Nx_points`. The `num_points=` and `dimension=` constructor arguments stay, without a warning.
    - `TensorProductGrid.get_boundary_handler(custom_conditions=)`: store a `BoundaryConditions` on the grid.
    - `ImplicitDomain.is_on_boundary(tol=)`: use `tolerance=`.
    - `NoFluxCalculator` and `FPNoFluxCalculator`: use `ZeroGradientCalculator` and `ZeroFluxCalculator`.
    - `get_ghost_values_nd`: use `pad_array_with_ghosts()` or `PreallocatedGhostBuffer`. `high_order_ghost_dirichlet` and `high_order_ghost_neumann` (#1936): use `ghost_cell_dirichlet` and `ghost_cell_neumann`.
    - `absorb_positions`: use `absorb_at_walls` for an absorbing wall, or `np.clip` for a clamp. `ParticleApplicator.apply_with_flux_limits`: use `apply`; a capacity-limited exit has no particle replacement.
    - The fdm_bc_1d names `BoundaryConditions1DFDM` and `LegacyBoundaryConditions1D`: use `BoundaryConditions` (see the #869 entry).
    - `UnstructuredMesh.visualize_mesh(show_edges=, show_quality=)`: use `mode=`.
    - `mixed_bc` stays, without a warning.
  - **Factories.**
    - `create_solver`, `create_basic_solver`, `create_standard_solver`, `create_fast_solver`, `create_accurate_solver`, `create_research_solver`, `create_semi_lagrangian_solver` and `create_amr_solver`: use `problem.solve()`.
    - `create_mfg_problem`, `create_general_mfg_problem`, `create_standard_problem`, `create_network_problem`, `create_variational_problem`, `create_stochastic_problem`, `create_highdim_problem`, `create_lq_problem` and `create_crowd_problem` (#1920): build the problem directly.
  - **Modules and utilities.**
    - Modules: `mfgarchon.operators.nonlocal_ops` (use `mfgarchon.operators.integro_diff`), `mfgarchon.utils.numerical.sdf_utils` (use `mfgarchon.geometry.implicit.sdf_utils`), `mfgarchon.utils.numerical.gfdm_operators` with `GFDMOperator` (use `mfgarchon.alg.numerical.gfdm_components.gfdm_strategies.TaylorOperator`), `mfgarchon.utils.numerical.particle.boundary` and its `apply_boundary_conditions_gpu`/`_numpy` re-exports from `mfgarchon.utils.numerical.particle` (use `mfgarchon.utils.particle_utils`) and `mfgarchon.utils.parameter_migration`.
    - The type aliases `SpatialCoordinates`, `TemporalCoordinates` and `LegacySolverReturn`: use `SpatialGrid`, `TimeGrid` and `SolverReturnTuple`.
    - `tensor_diffusion`: use `diffusion`.
    - `validate_u_final`: use `validate_u_terminal`.
    - `validate_adjoint_capability`: use `validate_scheme_pairing`.
    - `calculate_l2_convergence_metrics`: use `sweep_change`.
    - `LocalRBFOperator(phs_order=)`: use `kernel="phs3"`. `compute_gfdm_parameters(overdetermination=)`: use `effective_overdetermination=`; its result's `overdetermination` key is gone, use `nominal_overdetermination`.
    - `resolve_volatility`'s `legacy_key=` and `legacy_is_squared=`.
    - `BaseOptimizationSolver.get_domain_constraints` and `BaseNeuralSolver.get_boundary_target_values`: read `BoundaryConditions.segments` through `mfgarchon.geometry.boundary.types.segment_value`.
  - **The machinery.** `FixedPointIterator`'s by-name refusal of the seven `damping_*` keywords removed in v0.25.0 (#1070), which raised `ValueError` with the `relaxation_*` name to use: they now get Python's `TypeError`. `mfgarchon/utils/deprecation.py` (`deprecated`, `deprecated_parameter`, `deprecated_value`, `retired_parameters`, `NEVER_READ`, `WRAPPER_FRAMES`, `validate_kwargs` and the registry scan); the retired-keyword refusals in `mfgarchon/utils/pde_coefficients.py` (`retired_volatility_keywords`, `retired_sigma_keyword`, `retired_sigma_at_n_keyword`, `retired_sigma_and_kind_keywords` and their tables `RETIRED_VOLATILITY_KEYWORDS`, `RETIRED_SIGMA_KEYWORD`, `RETIRED_SIGMA_AT_N_KEYWORD`), so `sigma=`, `sigma_kind=`, `sigma_at_n=`, `sigma_function=` and the per-solve `volatility_field=`, `volatility_matrix=`, `diffusion_field=` and `tensor_diffusion_field=` now get Python's own `TypeError`; the deprecation ratchet and guide (`scripts/check_internal_deprecation.py`, `scripts/generate_deprecation_guide.py`, `scripts/audit_deprecated_symbols.py`, `scripts/pre-commit-deprecation-check.sh`, `scripts/deprecation_baseline.json`, `.github/workflows/deprecation-check.yml`); and the warnings themselves, among them the components= form's warning (a `DeprecationWarning` in the last release) and the components BC's `DeprecationWarning`. `MFGComponents.boundary_conditions` stays, without a warning.
  - **Documents.** `docs/user/DEPRECATION_MODERNIZATION_GUIDE.md` and `docs/user/LEGACY_PARAMETERS.md`, and the documents whose subject is a removed API or a past release's migration: `docs/user/three_mode_api_migration_guide.md`, `docs/user/migration_v0.19.md` and `docs/user/dual_geometry_usage.md`. Git history keeps them.
  - **Attributes.** Reading a removed attribute raises `AttributeError`. Assigning one succeeds and has no effect, as for any name Python does not know, except on `PicardConfig` and `MFGGridConfig`, which raise `ValueError`, and on the frozen dataclasses `HamiltonianValues` and `GraphBCConfig`, which raise `FrozenInstanceError`, for any unknown name. Before this change, 16 reacted to assignment. `NewtonMFGSolver.newton_tolerance` and `HJBFDMSolver.on_newton_failure` were read after it (use `solve(absolute_tolerance=)` and `on_inner_failure`). Fourteen were properties with no setter, so assigning one raised: the `damping_factor` attributes of `BlockIterator`, `MultiPopulationIterator`, `HJBFDMSolver` and `FixedPointSolver`, and `BlockIterator.damping_factor_M`; `problem.sigma`, `Model.sigma`, `VariationalMFGProblem.sigma` and `HamiltonianValues.sigma`; `problem.volatility_field`, `problem.diffusion_field` and `problem.spatial_discretization`; `ControlCostBase.control_cost`; and `TensorProductGrid.num_points`.
  - **A deleted positional parameter makes every later parameter keyword-only.** That covers never-read inputs, deprecated parameters and `MFGComponents`' fields after `u_terminal`. A positional caller past that point gets Python's `TypeError` instead of having its arguments shifted onto the next parameter.
