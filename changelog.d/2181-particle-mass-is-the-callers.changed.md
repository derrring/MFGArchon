- **`FPParticleSolver`'s default `kde_normalization` changes from `ALL` to `INITIAL_ONLY`** (Issue #2181). Every caller that did not name the parameter inherits this silently, so it is recorded separately from the fix. Since the same change makes every slice measured on `geometry.integrate`'s measure, `ALL` pins exactly what `SolverResult.mass_conservation_error` reports: measured, that diagnostic reads **2.220446e-16** for any completed solve, which is mass conservation by fiat rather than by the scheme. #1683 removed that shape from `fp_fdm`, `fp_gfdm` and `network_solvers/fp_network`, and this solver was the campaign's surviving instance. Under the new default t=0 carries the caller's mass exactly and every later slice carries one factor, so the reconstruction's own drift stays measurable: the same fixtures now report 3.2e-03 to 1.26e-02 where they reported 2.2e-16. `ALL` remains available and is documented as fiat. `ParticleConfig.normalization` already defaulted to `"initial_only"`, so this removes a pre-existing divergence between the config surface and the solver rather than creating one.
