- **`cfl_target` for the semi-Lagrangian pair must lie in (0, 1], and `SLConfig.cfl_number` now sets it (#2448).** `cfl_target` is the crossing a sub-step is *planned* for: the cells its foot would cross at the velocity measured at the step's start. The HJB half's traced feet run past it (#2439), and a step whose CFL number is at most 1 is not split at all, so its foot can cross up to one cell whatever `cfl_target` is. `HJBSemiLagrangianSolver` took any positive value. On #1880's matrix fixture (σ = 0.2), with the HJB half at c and the FP half at its default, a seeded asymmetry changes per sweep by 0.984 at c = 1.0, 1.005 at 1.02, 0.994 at 1.05, 1.121 at 1.1 and 2.190 at 1.5: growth starts just above 1, not monotonically, and the margin at 1 is thin. Both constructors, and `cfl_substeps`, now refuse a value outside (0, 1]. `FPSLSolver`'s `cfl_target` (new with #1880) shares the range, because the pair factory hands the HJB half's value to it; an FP half at up to 1.5, beside a default HJB half, was stable. `max_substeps` = NaN, which switched the cap off, is refused too.
  - `SLConfig.cfl_number` raised `NotImplementedError` for any value but its default, and an explicitly set default (0.5) was silently ignored while the solver ran at 0.9. It now defaults to None, meaning the solver's own. A set value reaches the HJB half as `cfl_target`, and the pair factory hands it to the FP half. A config that set 0.5 now runs at 0.5.
