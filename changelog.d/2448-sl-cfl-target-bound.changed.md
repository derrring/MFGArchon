- **`cfl_target` for the semi-Lagrangian pair warns above 1 and must be positive and finite, and `SLConfig.cfl_number` now sets it (#2448, #2458).** `cfl_target` is the crossing a sub-step is *planned* for: the cells its foot would cross at the velocity measured at the step's start. The HJB half's traced feet run past it (#2439), and a step is not split at all while its CFL number is at most max(1, `cfl_target`), so an unsplit foot can cross that many cells. `HJBSemiLagrangianSolver` took any positive value. On #1880's matrix fixture (σ = 0.2), with the HJB half at c and the FP half at its default, a seeded asymmetry changes per sweep by 0.984 at c = 1.0, 1.005 at 1.02, 0.994 at 1.05, 1.121 at 1.1 and 2.190 at 1.5: growth starts just above 1, not monotonically, and the margin at 1 is thin. Both constructors now warn above 1, quoting the growth measured above 1, and they and `cfl_substeps` refuse a value that is not positive and finite. Above 1 is not refused: the threshold is one fixture's measurement, not a property of the scheme (#2458). `FPSLSolver`'s `cfl_target` (new with #1880) gets the same check, because the pair factory hands the HJB half's value to it; an FP half at up to 1.5, beside a default HJB half, was stable. `max_substeps` = NaN, which switched the cap off, is refused too.
  - `SLConfig.cfl_number` raised `NotImplementedError` for any value but its default, and an explicitly set default (0.5) was silently ignored while the solver ran at 0.9. It now defaults to None, meaning the solver's own. A set value reaches the HJB half as `cfl_target`, and the pair factory hands it to the FP half. A config that set 0.5 now runs at 0.5.
