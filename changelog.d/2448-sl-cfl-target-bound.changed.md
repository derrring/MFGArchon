- **`cfl_target` for the semi-Lagrangian pair must lie in (0, 1], and `SLConfig.cfl_number` now sets it (#2448).** `cfl_target` is the number of cells a sub-step's foot may cross, and both `HJBSemiLagrangianSolver` and `FPSLSolver` took any positive value. On #1880's fixture an HJB half at 1.5 grew a seeded asymmetry 2.190x per sweep (σ = 0.2), and at 50 either half behaved as if it did not sub-step. Both constructors, and `cfl_substeps`, now refuse a value outside (0, 1].
  - `SLConfig.cfl_number` raised `NotImplementedError` for any value but its default, and that default (0.5) was never the solver's (0.9). It now defaults to None, meaning the solver's own, and a set value reaches the HJB half as `cfl_target`; the pair factory hands it to the FP half. Its existing bound, at most 1, is the same as the solvers'.
  - `create_paired_solvers` given an `fp_config` that undoes the sub-step match now builds the pair and warns, instead of raising as #2443 made it. Discrete adjointness is a property to report, not a gate. The warning states the cost: on #1880's fixture such a pair diverged.
