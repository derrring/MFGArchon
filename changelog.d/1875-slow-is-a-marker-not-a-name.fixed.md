- **A test is slow when it carries `@pytest.mark.slow`, no longer when its name contains "large", "slow" or "benchmark"** (Issue #1875). The gate deselects `slow`, so the name rule in `tests/conftest.py` kept descriptive, fast tests out of it with nothing at the test to show it. At `bfdab257` it held 31 cases out, and a pytest session over all 31 takes under a second, collection included. Among them was #1684's pin that `MultiPopulationResult.errors` takes the max over fields. The gate collects 4735 tests where it collected 4695: those 31, and this change's own nine.
  - A test whose function name has "slow" as an underscore-separated word must carry `@pytest.mark.slow`. It fails at setup otherwise, before an `xfail` marker can absorb the failure, with a message that says to rename it or declare it.
  - `scripts/oracle_pins.txt` declares what #2512's progress counts: 38 oracle cells, 10 (b) rows, conventions C1–C6, and five pins, each with the tests that meet it or `-` if none does yet. The gate's suite run now writes its results as JUnit, and a new step, `scripts/check_oracle_pins.py`, fails unless every listed test passed in that run. A listed test that is deselected, skipped, xfailed, failed or no longer collected turns the gate red, and so does a results file that is missing, empty, unparseable, not xunit1 or from another run, or a manifest file pytest cannot collect. The step prints how many items of each kind are met, which a merge report quotes for #2512; it checks that every listed test passed, not the counts themselves.
