- **The meshless Galerkin pair places Dirichlet conditions on whole faces only, and refuses what it cannot place** (#2490; #2512, convention row 5). **Behaviour change:** some inputs that constructed now raise `NotImplementedError` at construction; `region_name` face labels and layered priorities, which solved wrongly, now solve correctly; and `boundary="all"`, which was refused with a DIRICHLET default or raised as a Dirichlet segment, now solves.
  - **One placement, read by the Nitsche assembly, the default-DIRICHLET guard and the pure-Neumann answer.** `nitsche._segment_faces` gives the faces a segment names; `_dirichlet_faces` gives each Dirichlet segment the faces no earlier segment in priority order claims, ties by declaration order, as `get_bc_at_point` reads them. The guard used to read `BoundaryConditions._segment_covers`, which counts a segment placed by `region` as covering the faces it names (#2490) and `boundary="all"` as covering none (#1953).
  - **Refused: a Dirichlet segment placed by `region`, `sdf_region` or `normal_direction`.** This path cannot read those fields. It dropped `region` and `normal_direction`, sending a segment with no `boundary` to every face and one with a `boundary` to that whole face; `sdf_region` it misread (next bullet). Measured at 11 points, δ = 0.35, σ = 0.3, T = 0.5, m0 = 1, zero drift: `region={0: (0.5, 1)}` absorbed 0.6652, the both-walls figure, where x_max alone gives 0.8326.
  - **`sdf_region` in particular:** the path integrated it on its zero level set, the curved-boundary design of #1139. `BCSegment` documents `sdf_region` as selecting the part of the boundary where it is negative. For a ball of radius 0.2 centred on a corner of the unit square, the conditions landed on a quarter circle inside the domain (7 quadrature points at the path's 16-cell floor, none on the boundary); for an SDF selecting a whole face (`1 − x`) the level set is the face but its normal points inward (FP mass ratio 0.9293, where the face alone gives 0.8326). That branch and the now-unused `surface_quadrature` are removed; #1139 records how to restore them under their own semantics.
  - **Refused: a segment this path cannot place that outranks a Dirichlet segment** (a `region`, an unknown `boundary` name), since it could take a face from it; the message says so. A lower-priority one cannot, and is not read.
  - **Refused: a segment this path cannot place, together with a DIRICHLET `default_bc`** (every segment is read for coverage then). The guard used to count it as covering the faces it names, so a face the resolver gives to the default was solved as no-flux (FP mass ratio 1.0000).
  - **Fixed: `region_name="x_max"` is now the face x_max.** It was imposed on every face (0.6652); it now solves exactly as `boundary="x_max"` (0.8326).
  - **Fixed: `boundary="all"` names every face** (#1953). A NO_FLUX `"all"` segment with a DIRICHLET default constructs again (#2523 refused it). A Dirichlet `"all"` segment, which raised at assembly, is now imposed on every face no higher-priority segment claims.
  - **Fixed: precedence.** A face named by several segments is the highest-priority one's, as `get_bc_at_point` resolves it. A no-flux `boundary=None` segment of priority 1 over a Dirichlet x_max used to leave the Dirichlet imposed (FP mass ratio 0.8326, the x_max-wall figure, where the resolver gives no-flux everywhere, 1.0000). A priority -1 Dirichlet `"all"` under a priority 1 Dirichlet x_max holds each face at its own segment's value.
  - **The translator alone decides absorbing.** The meshless FP built its Nitsche terms without the value (`include_data=False`), deciding Dirichlet → absorbing a second time. Both solvers now assemble the data load from the BC they hold. The FP holds the shared BC read through `fp_view_of_shared_bc`, where a Dirichlet value is 0, so it still absorbs, bit-identically. The `include_data` parameter is gone.
  - The BC guide's NEUMANN note said a nonzero Neumann value is "silently ignored by every FP solver". Every grid FP solver now refuses it at construction (FDM, FVM, GFDM, SL and particle since #1686, FEM since #2294, the meshless pair since #2523), and the note says so.
  - **A zero the translator accepts is a zero here.** The Nitsche data reader takes its "verifiably zero" from `bc_utils._describe_bc_value`, so `np.int64(0)`, `np.zeros(1)` and `None` absorb on the FP, bit-identically to main; on the HJB, where main raised, they impose 0. Any real scalar or size-1 real array is read as a value; a complex one is refused (`float()` would drop its imaginary part).
