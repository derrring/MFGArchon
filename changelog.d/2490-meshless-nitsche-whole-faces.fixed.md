- **The meshless Galerkin pair places Dirichlet conditions on whole faces only, and refuses what it cannot place** (#2490; #2512, convention row 5). **Behaviour change:** some inputs that constructed now raise `NotImplementedError` at construction, and two that solved wrongly now solve correctly.
  - **One predicate, `nitsche._segment_faces`, says which bounding-box faces a segment governs.** The Nitsche assembly imposes Dirichlet data there, and the default-DIRICHLET guard counts coverage with it. The guard used to read `BoundaryConditions._segment_covers`, which disagrees with the point resolver on restricted segments (#2490) and on `boundary="all"` (#1953).
  - **Refused: a Dirichlet segment restricted by `region`, `sdf_region` or `normal_direction`.** It was stretched onto whole faces. Measured at 11 points, δ = 0.35, σ = 0.3, T = 0.5, m0 = 1, zero drift: `region={0: (0.5, 1)}` absorbed 0.6652, the both-walls figure, where x_max alone gives 0.8326.
  - **`sdf_region` in particular:** the path integrated it on its zero level set, the curved-boundary design of #1139. `BCSegment` documents `sdf_region` as selecting the part of the boundary where it is negative. For its own exit-disk example on the unit square, the conditions landed on a quarter circle inside the domain (7 quadrature points, none on the boundary). That branch and the now-unused `surface_quadrature` are removed; #1139 records how to restore them under their own semantics.
  - **Refused: a segment restricted to part of a face, together with a DIRICHLET `default_bc`.** The guard used to count it as covering the face, so the uncovered part was solved as no-flux (FP mass ratio 1.0000).
  - **Fixed: `region_name="x_max"` is now the face x_max.** It was imposed on every face (0.6652); it now solves exactly as `boundary="x_max"` (0.8326).
  - **Fixed: `boundary="all"` governs every face.** A NO_FLUX `"all"` segment with a DIRICHLET default constructs again (#2523 refused it). A Dirichlet `"all"` segment, which raised, is now imposed on every face.
  - **The translator alone decides absorbing.** The meshless FP built its Nitsche terms without the value (`include_data=False`), deciding Dirichlet → absorbing a second time. Both solvers now assemble the data load from the BC they hold. The FP holds the shared BC read through `fp_view_of_shared_bc`, where a Dirichlet value is 0, so it still absorbs, bit-identically. The `include_data` parameter is gone.
  - The BC guide's NEUMANN note said a nonzero Neumann value is "silently ignored by every FP solver". It has been refused at construction since #1686, and the note now says so.
