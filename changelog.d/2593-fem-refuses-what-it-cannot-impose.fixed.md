- **`HJBFEMSolver` and `FPFEMSolver` refuse, at construction, a boundary condition the FEM adapter would misread in silence** (#2593). The adapter imposes conditions segment by segment. Measured below on a 16-element mesh of [0, 1], with the wall on x_min and the exit on x_max.
  - **A Dirichlet value it cannot read.** It read every constant but a plain `int` or `float` as 0, so HJB-FEM held u = 0.0000 at an exit given as `np.float32(0.7)` or as the string `"0.7"`. Now:
    - a finite real number, NumPy scalars included, or a finite 0-d real array is its value, and HJB-FEM holds 0.7000 there;
    - `None` and an all-zero array are 0, as the library's test for a verifiably zero datum reads them;
    - a callable is read as `g(x)`;
    - anything else is refused: a string, a `Decimal`, a provider, a 1-d array that is not all zero, a complex or boolean value, a non-finite number.
    FP-FEM's shared route is unchanged, since a shared DIRICHLET reaches it as an exit, m = 0. FP-FEM's own BC (#2532) is checked as HJB-FEM's is.
  - **A `default_bc=DIRICHLET` left to govern boundary facets no segment names.** The adapter never reads `default_bc`, so those facets got the natural condition: a wall where an exit was asked for. FP-FEM's density stayed 1.0000 at x_max, and HJB-FEM held u = 0.0000 there, not 0.7. Give each Dirichlet face its own `BCSegment(boundary=...)`. `dirichlet_bc(g)` is unaffected: its one segment names the whole boundary.
  - **Under a `default_bc=DIRICHLET`, a segment of any type naming a boundary the mesh does not tag raises `ValueError`**, listing the tags, as a Dirichlet segment's already did (#1489). A library alias such as `"left"` is one: the BC layer reads it as `x_min` (`parse_boundary_face`), and both FEM solvers solved a no-flux wall named so correctly before. Name the mesh's tag instead. FEM resolves a segment's facets by the mesh's tags alone, a disagreement filed on #2512 (row B1). A segment also placed by `region`, `region_name`, `sdf_region` or `normal_direction` claims its whole `boundary` face, or the whole boundary if it names none.
  - The last two apply only where a DIRICHLET default is set. `BoundaryConditions.default_bc` defaults to `None`, and the deprecated `mixed_bc` to NEUMANN.
