- **Every term in the HJB is cost-signed: the Hamiltonian is `H = H_control(p) - V - f(m)`** (#2375 rulings 3–4, #2378 phase 2). **This changes computed values.** Any result that depends on a `potential`, a `coupling` or a `state_penalty` moves when this lands, including in-flight experiments.
  - **What changed.** `V` and `f` used to enter `H` with a plus sign, so a positive `V` lowered `u` and acted as a reward, while the terminal cost and `source_term_hjb` were costs. One `u` carried two meanings. Now every term is something the agent pays: written with all of them on the right-hand side, `-u_t + H_control(Du) - (σ²/2)Δu = V + f(m) + S`. The running cost is `L = L_control + V + f`, and `H = sup_α{-p·α - L}` holds for both sides, which flipped together.
  - **What to change in your code.** An attractive potential is now a bowl with its minimum at the target, `V = +C (x - x_c)²`, not an inverted parabola. A congestion coupling is an `f` that increases with `m`, e.g. `f(m) = m` or `m²`. If you negated `V` or `f` to get the behaviour you wanted, remove the negation. Code written to the intuitive sign now means what it says: #2350 measured all 26 examples that pass `coupling=` as written that way, and they are unchanged.
  - **`∂H/∂m = -f′(m)` and `∂H/∂x = -∇V`.** Lasry–Lions monotonicity is stated on `f`: increasing in `m` means crowd-averse. The optimal control `α* = -∂_p H` does not change, since `V` and `f` do not depend on `p`. The equilibrium moves through `u`.
  - **`QuadraticMFGHamiltonian`** (and `create_hamiltonian("default")`) now carries `f(m) = m²` with `∂H/∂m = -2m`. It was crowd-averse before and still is; the stored sign changed so that the behaviour did not.
  - **`state_penalty`** is added to `V`, since both are costs. A wall still raises `u` where it is expensive.
  - **Networks.** `NetworkHamiltonian` returns `control - (V + f)`, and the RK45 HJB adds `H` whole (`du/ds = -H`). With the built-in network Hamiltonian, values do not change. A user-supplied `hamiltonian_func` is now the **whole** Hamiltonian, cost-signed: write `control - V - f` inside it. **Only the RK45 HJB solver honours it**, and policy iteration and the network FP solver now **raise** for a problem that has one. Both take the built-in control whatever `H` says (#1545), so they used to solve a different problem silently. A custom network `H` is therefore usable for a standalone RK45 HJB solve, and not for a coupled MFG solve, until #1545 lands. Its RK45 values change: the solver used to compute `-(H - source) + source`, adding the source term a second time (the declared one, or the default `m²/2` congestion when none was declared). Passing `node_potential_func` or `node_interaction_func` alongside a custom `hamiltonian_func` raises, because the RK45 solve would not read them.
