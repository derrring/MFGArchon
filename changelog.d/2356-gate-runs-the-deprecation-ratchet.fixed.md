- **The local gate now runs the deprecation ratchet, which it never did** (Issue #2356).
  - `scripts/local_ci.sh` is the authoritative gate, run through the pre-push hook. It invoked `scripts/check_internal_deprecation.py` **only in its `--self-test` loop** and never as the ratchet; the ratchet ran solely in `.github/workflows/deprecation-check.yml`. So a PR that *retires* a deprecation passed the gate **by construction** and failed on the runner.
  - **Not hypothetical.** #2355 removed seven deprecated symbols, `local_ci.sh` reported `GATE GREEN` twice, and CI was red: `total: 59 -> 51, type:function: 22 -> 16, type:parameter: 36 -> 34`. The checker's own message says to regenerate "in the commit that does the work" — and nothing local ever printed it, because nothing local ever ran it.
  - **No `--check-baseline` argument, and the issue that proposed this asked for one.** This checker has no such flag; it hardcodes `BASELINE = Path(__file__).resolve().parent / "deprecation_baseline.json"`, so the bare invocation *is* the ratchet — the same line the workflow runs. `check_fail_fast`, `check_doc_api` and `check_docstring_kwargs` each take a path, and copying their idiom produces an argparse error rather than a check. The style neighbour is therefore the Manifest ratchet, which takes no argument either — so this step is the **second** of that shape, not an exception to a rule. Measured against `--help`, not assumed. (A first draft said "the four baseline ratchets above" and "the gate's only no-argument ratchet": three take a path, the fourth is the Manifest ratchet the same sentence then named, and this change makes "only" false as it lands.)
  - **Unguarded by `--fast`**, like every ratchet outside the two `$FAST -eq 0` blocks — and those blocks are not ratchet-free: the first holds the capability matrix's own `--check-baseline` before the test suite, the second the discrimination report. The comment above `probe_modules` already names this script as the reason `--fast` cannot run on a package-less interpreter, so the file had already committed to it running in both tiers.
  - **Oracle, both directions, in the gate and standalone.** Reverting `scripts/deprecation_baseline.json` to its pre-`c8851eaf` content (total 59) makes the step exit 1 and name the drift per key with its direction; restoring it returns exit 0 and `Matches baseline`. A gate step that cannot go red is the defect this change exists to remove, so it is verified red before it is trusted green.
  - **The verdict names both branches this checker can fail on.** One draft said "no deprecation added or retired", which claims more than the check measures; the next said "net count", which claims less. Measured, there are two branches. **Counts** are compared *per kind* over the key union, so a cross-kind swap — retire a function, add a parameter — **is** caught; only a **same-kind** swap leaves every key equal, which is narrower than "a swap" and is what #2363 now records. **Identities**: `production_uses()` walks the AST for calls to symbols whose `internal_usage` is cleared and returns 1 on any hit, nothing to do with counts — dormant today at `internal_usage_cleared: 0`, and going live exactly as #2343's removal batches land. The checker's own green line already names both, so the verdict now reads **"no deprecation count moved, and no cleared symbol is still called in production"**. `58bb2c59` is the same identities-not-counts fix for citation drift.
  - **Scope.** `scripts/check_docs_structure.py` is the other check CI runs and the gate does not, and it stays out — `docs_audit.yml` runs it with **`continue-on-error: true`**, so it cannot fail a PR today and there is no CI-blocks/gate-does-not asymmetry to close. The remaining question is whether it *should* gate at all, which is a separate judgement and not this change's to make.
