- **The node a network solver hands a Hamiltonian as `x` is an `int`** (#3012). `GraphGeometry.node_x(i)`, new, builds it, and the network solvers hand it at each door: `FPNetworkSolver`'s rates, `NetworkPolicyIterationHJBSolver`'s rates, and `NetworkHJBSolver`'s source and Hamiltonian. The rates handed `np.array([i])`, so a `NetworkHamiltonian` subclass that indexes `x` there sees an `int` now.
  - **A `NetworkHamiltonian` method you call yourself** takes the node as an `int`, a numpy integer or an array of one integer entry, one of the graph's nodes, through `node_x`. It now refuses by name every other form it used to read through `int(np.asarray(x).flat[0])`: an array of more than one entry (it read the first), a float, a bool, a string, a complex, a list or a tuple (each read as the integer it held), and a negative or out-of-range index (`-1` read as the last node).
- **A network solver refuses by name, at construction, a problem it cannot read** (#2045, #1472): one that lacks the network data, the Hamiltonian's methods, or the node-BC readers a network solve takes. On an `MFGProblem` built on a network geometry, `FPNetworkSolver` raised a bare `AttributeError` there; the HJB solvers refused it by name already.
- **A network solver refuses to solve once the geometry's graph has been rebuilt** since the solver was built (#1472). The network geometry counts its builds (`graph_generation`), and the Hamiltonian and the problem read its current graph.
