- **The node a network solver hands a Hamiltonian as `x` is an `int`** (#3012). `GraphGeometry.node_x(i)`, new, builds it, and the network solvers hand it at each door: `FPNetworkSolver`'s rates, `NetworkPolicyIterationHJBSolver`'s rates, and `NetworkHJBSolver`'s source and Hamiltonian. The rates handed `np.array([i])`, so a `NetworkHamiltonian` subclass that indexes `x` there sees an `int` now.
  - **A `NetworkHamiltonian` method you call yourself** takes the node as an `int`, a numpy integer or a one-entry array of integer dtype, one of the graph's nodes. It now refuses by name every other form it used to read through `int(np.asarray(x).flat[0])`: an array of more than one entry (it read the first); a float, a bool, a string, a complex, a `Fraction`, a `Decimal`, a list, a tuple, an object array or a bool array (each read as the integer it held); `-1` (the density, costate and neighbours read at the last node, and your own callables handed `-1`); and `N`, one past the last node (your own callables handed `N`, and the reads that index the graph raising `IndexError`).
- **A network solver refuses by name, at construction, a problem it cannot read** (#2045, #1472): one that lacks what that solver reads from it: the network data; the problem's Hamiltonian (the HJB solvers); the Hamiltonian's `has_custom_hamiltonian` (`FPNetworkSolver` and policy iteration). `FPNetworkSolver` raised a bare `AttributeError` there.
- **A network solver refuses to solve once the geometry's graph has been rebuilt** since the solver was built (#1472). The network geometry counts its builds (`graph_generation`), and the Hamiltonian and the problem read its current graph.
