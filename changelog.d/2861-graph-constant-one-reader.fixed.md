- **A graph node's constant is read by the reader its return is read by, so a NaN or an infinity is refused** (Issue #2861). `NodeBC(value=)`, `set_dirichlet_nodes`, `set_source_nodes`, `apply_direct`, the `boundary_value=` and `source_value=` of `create_graph_applicator`, and `from_network_geometry(boundary_value=)` wrote a non-finite constant into the field, where a grid boundary value refuses one (#2593) and a graph callable's return was already refused. An FP source on a network solved with non-finite entries in its density, and an HJB exit stopped at a `ConvergenceError` that did not name the constant. Each door now raises `NotImplementedError`. A NEUMANN node's NaN or infinity keeps its own refusal, as a flux that would be dropped. An int too large for a float, which raised Python's unnamed `OverflowError` from a grid constant and from either kind of return, is refused by name too. At a door that takes one value, a graph constant otherwise takes what it took: `None`, a masked element and a one-element array stay refused by name, where a grid constant reads them. `apply_direct`'s `values` still takes a list, tuple or array of one value per node.
