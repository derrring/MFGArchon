- **Every callable you hand the library is read by the names it declares, and `x` is a coordinate tuple** (Issue #2875, stage 2; #2872, #2877, #2481; user rulings 2026-11-04). **Breaking.** `x` holds one entry per coordinate, each a scalar or an array of one shape, so a body reads `x[0]` and `x[1]`, `sum(xi**2 for xi in x)` or `np.linalg.norm(x, axis=0)`, whether it is handed one point or many. See `CONVENTIONS.md` § *Callable signatures*.
  - **Now refused, or raising where it read before:** `x` as an array in every role, so `x**2`, `x - 0.5`, `x[:, 0]`, `x[..., 0]` and `np.asarray(x)[:, 0]`; any parameter with no default named for no slot; `*args` and `**kwargs`; a positional-only parameter; a callable that is not a function you wrote; expanded coordinates `(x, y)`; `time`, `m_t` and `v_t` for `t`, `m` and `v`; `t` where the role takes `t_idx`, as Howard's `alpha_star` and `running_cost` do. A `lambda c=0.7, x=0.0: ...` now reads the point in `x` and keeps `c` at its default: it read the point in `c`, and solved with no error (#2872).
  - **A body must read a batch and a point the same.** One check makes that comparison, in two functions, `_compare_reads` and `refuse_batch_disagreement` for a Hamiltonian, replacing `require_batch_safe_hamiltonian`. `MFGProblem` makes it on its conditions, potential, `state_penalty` and Hamiltonian, and any other door at its first batch, before returning the result. A body is marked compared once a comparison agrees with two or more distinct points among the rows it compares; a refusal is not kept, so a later read compares again. A body handed no `x` is not compared: a coupling and its derivative, a congestion factor and its derivative, Howard's running cost and control Lagrangian, and a network's node terms. A point-only Hamiltonian such as `0.5*p[0]**2` is refused when a problem takes it, on every path and in every dimension (#2481); one that solved on the per-point path, `analytic_jacobian=False`, is refused too. Write it row-wise.
  - **Reads that were right and are refused now:** `lambda y:` for a condition, `lambda rho:` for a coupling, `np.sin` for a coupling, `lambda t, x, **kw:`, an interpolant, a `functools.cache` of a def, and a body holding an array with one entry per point at a door with no field: a solver's `source_term=lambda t, x: S`, a predicate `lambda x: mask`, a measure field. Wrap each in a function named for the slots it reads, and index a held array by what the point reads. `lambda t, x: S` still reads at `source_term_hjb` and `source_term_fp`, with `S` of the grid's shape. A partial that freezes by position is told to pass the frozen value by keyword, since renaming its parameters would move the value.
  - **A coupling or congestion factor is read on the batch, with nothing falling back to one point at a time:** `lambda m: float(m)`, `lambda m: math.log(m)` and a branch on `m` were read point by point when the batch read raised, and are refused now. A constant still holds for every point.
  - **A body written to per-axis vectors at FP-FDM changes form in 2-D:** `x[0][:, None]` and `np.meshgrid(*x, indexing="ij")` inside a body were read on per-axis vectors, and are refused now, since `x` holds the grid's coordinates at the grid's shape.
  - **A body's return is stated per door.** Everything takes a scalar or one entry per point. A door with a field also reads the entries of an array of the batch's shape that a point read returns whole, and a volatility or a diffusion also reads one fixed array. Anything else is refused as having no entry per point. So `u_terminal` and `m_initial` refuse a held array of any shape, as they did before, and `source_term_hjb` and `source_term_fp` refuse `(3, 5)` or `(15,)` on a `(5, 3)` grid, which read in C order. A constant vector is refused at a drift.
  - **Two more doors read by name with `x` a tuple:** `PotentialEnergy(potential, weights, V=...)`, whose `V` was handed the raw `(n, d)` array, so `lambda x: x[1]` read the second point and not the second coordinate at n = d with no error; and `HJBHowardSolver(control_lagrangian=...)`, whose `(c=3.0, alpha=0.0)` read `alpha` in `c`. `lq_mfg_terminal_cost` and `lq_mfg_initial_density` return tuple-form conditions.
  - **A constant source holds at every point:** `lambda t, x: 0.5` at `source_term_hjb`, or as a solver's `source_term`, raised `AttributeError`, and reads now.
  - **What the check cannot catch:** it reads a few samples of the first batch. A particle drift's first batch is the initial cloud, so a body reading past a dead zone the cloud has not reached is accepted, and is not compared again. At a field door, `m[0]` reads node 0 at every point and cannot be told from `np.max(m)`, since a point read gets the field whole; these doors had no check before. A door that only ever hands one point has nothing to compare. A refusal is not remembered, so a sweep that catches it and rebuilds its problem can be accepted where the new samples agree. A body accepted at a door that keeps its mark with the body, a problem's `u_terminal` among them, is not compared again at a new problem. A closure the library wrote is not compared, and the user's callable inside it has its own door. A `signed_distance` you write on a subclass of `ImplicitGeometry` is a method, keeps its array of points, and is not compared. On a square grid, `F` and `F.T` held at `source_term_hjb` both solve and differ, and no shape can tell them apart.
  - **Removed:** `mfgarchon.utils.callable_adapter` (`adapt_ic_callable`), `mfgarchon.utils.hamiltonian_adapter` (`HamiltonianAdapter`, `adapt_hamiltonian`, `create_hamiltonian_adapter`), `require_batch_safe_hamiltonian`, `detect_callable_signature`, `validate_drift`, `validate_running_cost`, `CoefficientMode`. `p` and a vector return are not changed here, and are #2875's stage 3.
