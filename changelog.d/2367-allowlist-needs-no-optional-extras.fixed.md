The example now uses `"numpy"`, which is always available, and names `torch`/`jax` in prose as taking the same form.
  - **The defect is the allowlist's selection predicate, not the example.** A module enters because its examples "already all pass" — measured on a developer machine where jax, torch and numba are installed. An example needing an extra is green on every local gate and red only in CI, invisible to its author by construction. That is recorded at the list itself, with the instruction to run a candidate's examples with the extra absent.
  - **The class is one example, measured rather than assumed.** With jax faithfully absent, all **24** allowlisted modules pass; only `backends` failed before this change.

A meta-path finder that *raises* propagates through `variational_mfg_solver.py`'s `find_spec("jax") is not None`, which expects `None` and receives an exception — the traceback dies in the finder, not in the code under test. What is faithful: a site-packages symlink farm omitting jax, so `find_spec` returns `None`, the import raises `ModuleNotFoundError`, and numpy survives. The control reproduces the nightly's exact text (`1 of 2 in mfgarchon.backends.create_backend`); the fix returns 0 failures against it.
