- **A docstring example in the executable allowlist required JAX, and main's nightly went red** (Issue #2367).
  - `mfgarchon.backends`'s `create_backend` example ran `create_backend("jax")`. The allowlist added by #2346 executes it, and the nightly unit job installs neither jax nor torch, so it raised `ImportError: JAX backend requested but JAX is not installed` — **1 failure in 3935**, on the first nightly to run the list. The example now uses `"numpy"`, which is always available, and names `torch`/`jax` in prose as taking the same form.
  - **"The nightly installs no optional extras" is false, and this repo had already struck it.** `nightly.yml` runs `pip install -e ".[numerical]" --group dev numba`, so **numba is present** and jax and torch are not; `test_optional_backends_are_not_imported_eagerly.py` holds the per-workflow table and records that an earlier draft of a comment said *"CI installs no extras"*, calling it *"false and in the damaging direction"*. A first draft of this change reintroduced the same phrase in three places, one of them the public `create_backend` docstring. It matters practically: a maintainer testing with numba absent makes 20 modules unimportable and sees breakage unrelated to their candidate.
  - **The acceptance criteria certified the trap they warned against.** The comment's three checks — `find_spec` returns None, `import` raises `ModuleNotFoundError`, numpy survives — **all pass** on `sys.modules["jax"] = None`, the first trap it names. A maintainer reaching for it and validating against the stated criteria gets a false green, which is precisely the failure this change exists to prevent. A fourth check now discriminates: **`"jax" not in sys.modules`** — true absence leaves it out entirely, while the injection leaves it present-and-None.
  - **The defect is the allowlist's selection predicate, not the example.** A module enters because its examples "already all pass" — measured on a developer machine where jax, torch and numba are installed. An example needing an extra is green on every local gate and red only in CI, invisible to its author by construction. That is recorded at the list itself, with the instruction to run a candidate's examples with jax and torch absent.
  - **The class is one example, measured rather than assumed.** With jax faithfully absent, all **24** allowlisted modules pass; only `backends` failed before this change.
  - **All three obvious simulations give false results; none of them is the one that worked.** `sys.modules["jax"] = None` breaks scipy's array-API layer. A meta-path finder that *raises* propagates through `variational_mfg_solver.py`'s `find_spec("jax") is not None`, which expects `None` and receives an exception — the traceback dies in the finder, not in the code under test. A finder that *returns* `None` does not block at all — returning `None` means "I cannot handle this, try the next finder", and the next one resolves jax. What actually produced the numbers below was a **symlink farm of site-packages minus jax** (551 entries): the control reproduces the nightly's exact text (`1 of 2 in mfgarchon.backends.create_backend`) and the fix returns 0 failures against it. Because the farm removed only jax, it is evidence about jax and not about torch.
  - **A venv is the reproducible route, and it needs the line above the install line.** `python -m venv /tmp/nojax`, then `/tmp/nojax/bin/python -m pip install --upgrade pip`, then `/tmp/nojax/bin/pip install -e ".[numerical]" --group dev numba`. The upgrade is `nightly.yml:75` and is load-bearing: a fresh 3.12 venv ships pip 25.0.1, which answers `no such option: --group` (control: that pip accepts `--dry-run`). Dropping it hands a maintainer a usage error and pushes them back toward the three traps.
