  - **The baseline's `_measured_at.commit` is a pre-merge branch sha, and this repo squash-merges**, so it is unreachable the moment the PR lands. Measured 2026-09-18: main's baseline cites `76f2d9e8` and `git branch -a --contains 76f2d9e8` is empty; the stamp before it, `a70d9a06`, is equally orphaned. The sha stays for provenance, now beside a `reproduce` field in **both** artifacts — the writer emitted that field but neither shipped file had it, since both predate the code — naming the procedure that works (`git log --oneline --follow`, then its **first** entry: squash merges here are single-parent, so there is no merge commit to find), what it recovers (the tree the artifact *shipped in*) and what it does not (not necessarily the tree the sweep *ran on*). A broken anchor is worse than none, because a reader tries it, fails, and has nothing else.
  - **`owner` is now checked against the code.** It is recorded in both JSONs and was compared by nothing, while being the only place a reader learns what convention a mutation tests — and every `owner` fixture in the ratchet's own tests is a bare `"x"` placeholder, which is where the check was missing. Review then found it gated on `"owner" in entry`, so *deleting* the key skipped the comparison silently — `.get(..., _MISSING)` goes red where that form passed.
  - **The gate's mutation guard is pinned by locating the grep, not by splitting on its text.** The old test split `local_ci.sh` on the first occurrence of the marker's literal text and required `cannot_run` within 400 characters. It has both errors: rewrapping the comment above the guard put the literal at the start of a continuation line and the gate went red on an edit that changed no logic, while the mypy probe later in the same file prints the same literal, so reordering the two would let the real guard be deleted with the test still green. It now locates the grep **invocation**, which a comment cannot imitate, and requires `cannot_run` within 8 lines. Mutation-checked: guard disabled → red, `cannot_run` severed → red, a comment naming the grep → green.
