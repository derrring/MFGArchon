- **A `sense` that is not an `OptimizationSense` is refused, in the one place the sign convention is decided** (Issue #2341).
  - `sense` is the first positional parameter of both `ControlCostBase.__init__` and `MFGOperatorBase.__init__`, and both derived the sign as `1 if sense == OptimizationSense.MINIMIZE else -1` — reading anything that is not MINIMIZE as MAXIMIZE. In each class the next positional parameter is a number (`control_cost`, the alias of `lambda_`; and `finite_diff_eps`), so a weight passed positionally became the sense and flipped the convention in silence.
  - Measured at `65bcf659`: `L1ControlCost(1e-12)` gave `sense=1e-12`, `sign=-1`, and `lambda_` left at its 1.0 default — the issue recorded that `_lambda: 1.0` too. The consequence is not a cosmetic sign: on `p = [-1, 2]` the broken construction returns `optimal_control = [-1, 2]`, **bit-identical to `sense=MAXIMIZE`** and the exact negation of the intended `[1, -2]` (#1642's convention). For `L1ControlCost` the discarded `lambda_` compounds it — `evaluate` returns 2.0 where the intended call gives 5.999999999996.
  - **One owner:** `_sign_for_sense(sense, owner, weight_keyword)` both validates and derives, and the two copies of the expression are gone. `MFGOperatorBase` is the base of `HamiltonianBase` and `LagrangianBase`, and its `sense_sign` has 14 consumers, so the sibling site mattered: at `09eaaa28`, `SeparableHamiltonian(cost, None, None, None, 0.5)` gave `sense=0.5` and `sense_sign=-1.0` with nothing raised. AGENTS.md asks for the highest owning abstraction for a cross-cutting defect, and that is this function rather than either constructor. The sibling was found by the pre-merge review of #2345.
  - The refusal names the keyword the value most likely belonged to — `lambda_` for a cost, `finite_diff_eps` for an operator — and deliberately does **not** build a suggested call out of the class name: `_MoreauYosidaControlCost` takes neither, so `ClassName(lambda_=...)` would have been a recommendation that raises.
  - A **bool** is refused by the generic branch on purpose. `True` is an `int`, but advising `lambda_=True` would hand back a call that *succeeds*, storing `True` as a numeric weight, since the `lambda_ <= 0` guard accepts a bool. Every `numbers.Real` **except `bool`** takes the helpful branch — `float`, `int`, `np.float32`, `np.int64` and `Fraction`, measured; `bool` is itself a `numbers.Real`, and is the exclusion above. `Decimal` and `complex` are not `numbers.Real` at all and get the generic message. For `complex` that is measured-correct — `lambda_=1+0j` raises `'<=' not supported between instances of 'complex' and 'int'`, so the helpful advice would not construct — while for `Decimal` it is ABC registration and nothing else: `lambda_=Decimal("0.5")` constructs and yields the same `float64` control as `Fraction(1, 2)`, which does take the helpful branch.
  - **An `OptimizationSense` with no sign convention now raises** instead of acquiring MAXIMIZE's in silence, and this is reachable today rather than a guard against a future member: `object.__new__(OptimizationSense)` satisfies `isinstance` while being neither member, and both constructors reach the branch through it. It is pinned by test. (An earlier version of this fragment called the branch unreachable and unpinnable — the pre-merge review of #2345 disproved that in three lines. Its diagnostic also had to stop reading `sense.name` and `repr(sense)`, since `Enum` resolves both through `_name_`, so the refusal was raising `AttributeError` from inside its own message.)
  - **Not done, and each for a stated reason.** Making `sense` keyword-only: it would refuse `L1ControlCost(OptimizationSense.MAXIMIZE, 0.5)`, which is legal. An AST census finds 370 ControlCost constructor calls in `*.py` with exactly one positional (`_MoreauYosidaControlCost(base, epsilon)`), and the review extended it to 18 occurrences across 657 non-`*.py` files — notebooks, the quickstart, two CI workflows — with 0 positional. Coercing a string, which Issue #2341 listed as part of its first option: nothing in-tree passes a string sense, the enum is the single owner of the two values, and a coercion would be new API surface; the refusal names the members instead.
  - **Breaking** for a caller who passes a weight positionally today, which is the point: that call is already wrong and was silent. Pre-1.0, so no deprecation cycle (AGENTS.md § Deprecation policy).
  - A docstring in `MFGProblem`'s Hamiltonian example taught the broken shape, and **doctests run nowhere** — not in `pytest.ini`, `pyproject.toml`, `scripts/`, or any workflow — so nothing had ever executed it. Corrected, with two test docstrings that described the same call in prose. Not fixed here, and filed as #2346 rather than left as a sentence: that example is still executed by nothing, which is #674's failure mode a second time, and `tests/unit/test_geometry/test_tensor_grid_docstring_examples.py` is the repo's existing answer to it.
