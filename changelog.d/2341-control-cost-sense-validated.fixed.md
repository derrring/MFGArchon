- **`ControlCostBase` refuses a `sense` that is not an `OptimizationSense`** (Issue #2341).
  - `sense` is the first positional parameter, so a value meant for the control-cost weight landed there, and the sign derivation read anything that is not MINIMIZE as MAXIMIZE: `self.sign = 1 if sense == OptimizationSense.MINIMIZE else -1`. Measured at `65bcf659`, `L1ControlCost(1e-12)` gave `sense=1e-12`, `sign=-1` and **`lambda` left at its 1.0 default** — so the number the caller passed was replaced by a default, not merely misrouted. Nothing raised, `evaluate` returned finite values, and `optimal_control` returned the opposite sign, so the caller got a plausible Hamiltonian with an inverted control. It was found while writing a probe for #2313, which read a C¹ jump of 0.000 where the correct call gives 1.000.
  - The refusal names the call that works: `L1ControlCost(lambda_=1e-12)`. A `sense` of any other type — a misspelled string included — is refused the same way, since it too has no defined sign and the old code silently returned MAXIMIZE's.
  - **Breaking for a caller who passes a weight positionally today**, which is the point: that call is already wrong and was silent. Pre-1.0, so no deprecation cycle (AGENTS.md § Deprecation policy).
  - **Not done: making `sense` keyword-only.** That would also close this, and would additionally refuse `L1ControlCost(OptimizationSense.MAXIMIZE, 0.5)`, which is legal and means what it says. Of 370 ControlCost constructor calls in the tree (AST, not grep) exactly one passes a positional argument — `_MoreauYosidaControlCost(base, epsilon)`, whose signature is its own — so validation closes the silence without removing anything that works.
  - `hamiltonian.py:1386` taught the broken shape in a doctest (`SeparableHamiltonian(control_cost=QuadraticControlCost(1.0))`), and doctests do not run in the gate, so nothing had executed it. Corrected, along with two test docstrings that described the same call in prose.
