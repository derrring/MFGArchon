- **The kill matrix's resolver now checks the case, not just the function** (Issue #2358).
  - `test_every_killer_node_id_still_resolves` gates unresolvable killer node IDs at **zero**, which is right — #2285 established that a non-zero tolerance buys silence rather than a report. But it stripped the parametrisation (`p.split("[")[0]`) and grepped the file for the function, so an ID naming a **case** that can no longer be collected still "resolved" as long as its function survived. **444 of the matrix's 775 killer IDs are parametrised — 57.3%** — and that was the size of the blind spot.
  - **It had two occupants.** #2343's removal of `FPSLAdjointSolver` left `test_a_declared_bc_type_is_honoured[FPSLAdjointSolver-NEUMANN]` and `[…-NO_FLUX]` naming cases that cannot be collected, while the test stayed green: the function survives and still collects 33 other cases, which is exactly why a function-level check reads clean.
  - **Real collection, because static parsing cannot substitute.** `_surface_params()` builds its ids as `f"{name}-{bc_type.name}"` from a live class-introspection walk over `_SUPPORTED_BC_TYPES`, so `FPSLAdjointSolver-NEUMANN` is only producible by collecting — an AST or regex fix misses precisely the case this exists for. `-q -q`, not `-q`: `pytest.ini`'s addopts carries `--verbose`, so one `-q` nets to verbosity 0 and prints the indented tree instead of flat node IDs.
  - **The first version of this fix was itself a regression, caught in review.** It excused any file that collected **zero** tests, on the ground that a module-level `pytest.importorskip` makes one uncollectable. But *skipped* and *collected nothing* are different sets, and the difference is a detection-power loss: renaming the only test in `test_particle_multi_exit.py` (1 test, 1 killer ID) left the new check **green**, while the `def`-grep it replaces went **red and named it**. 31 killer IDs sit in files one ordinary edit could zero; adversarially 424 of 773 can be hidden under the count floor. The carve-out now reads the **skip report** (`-rs`): a file pytest names in a `SKIPPED [1] path:line:` line is excused, and a file that merely lost its tests is reported. `-rs` does not disturb the parse — SKIPPED lines do not start with `tests/`, so `collected` is byte-identical with and without it. Verified four ways: only-test-renamed → red and named; file emptied → red; `importorskip` broken to a missing module → green, excused; clean tree → green.
  - **Two new guards, both load-bearing.** `assert proc.returncode == 0` and `assert len(collected) > 2000`: a collection that fails, or silently produces nothing, leaves the stale list empty and the check reads green — the same shape as the collapsed-matrix control one layer up. And a file that collected **zero** tests is treated as *not measured*, never as dead: four matrix files carry a module-level `pytest.importorskip` (skfem, igraph, cvxpy) covering 8 killer IDs, which collect here but would all read as stale on a box without those extras.
  - **The two dead entries are removed BY HAND, and this is subtraction on proof, not a re-measurement.** The sweep costs 136 min and #2343 explicitly waives re-recording for a removal, so the record was edited directly: both IDs dropped from `killed_by` (775 → 773) and from `quadrature_wall_node_counting_measure`'s `killed`, with its `kill_count` **96 → 94** in the kill matrix *and* in the baseline the ratchet compares against. What is known is that those two cases are uncollectable; the other 94 were **not** re-measured. No mutation loses its last killer, and `uncovered` stays empty.
  - **The oracle ran in the order that proves it.** The fixed resolver was run *before* the entries were removed and went **red**, naming exactly those two IDs and nothing else. A bookkeeping fix applied first would have left no evidence the check had gained any detection power.
