- **A `SeparableHamiltonian` whose `optimal_control` is its own now drives the FP equation with it** (Issue #2900). Handed the value function, FP-FDM and the semi-Lagrangian solver formed the drift as $-c\,\nabla u$, the control cost's, so on `problem.solve()`'s default scheme a subclass that redefined $H$ solved with its base class's drift, with no error: 7.411e-01 off in $M$ from the library `SeparableHamiltonian` for the same $H$, its `optimal_control` called 0 times.
  - **Routed:** the coupling layer hands such a Hamiltonian to a velocity-channel solver (FP-FDM, FVM) as `drift_field`, which reads its `optimal_control`. It now solves as the library Hamiltonian it describes. That covers an `optimal_control` defined on the class, inherited from a subclass, wrapped with `functools.wraps`, or assigned on the instance.
  - **Refused:** a solver that forms $-c\,\nabla u$ from the value function refuses such a Hamiltonian, naming the schemes that read `optimal_control`. That is the semi-Lagrangian solver, FP-FDM called directly with `potential_field=`, the HJB-FDM linearized operator and the meshless HJB stabilization.
  - **Unchanged:** the particle solver and the weak-form family read `optimal_control` themselves, and keep solving it from the value function. FVM, which read it too, now takes the velocity route, with $U$ and $M$ bit-identical to before. Every library Hamiltonian keeps its route.
  - **Not yet:** a multi-population solve keeps the value-function route for such a Hamiltonian until its velocity door hands each population its own density (#2335), so FP-FDM refuses it there instead of solving it with the base drift.
