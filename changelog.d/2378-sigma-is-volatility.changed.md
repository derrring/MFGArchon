- **The agents' SDE volatility has one name, `volatility`, in every public API (#2378 phase 4 part 2b).**
  Breaking (pre-1.0; deprecation clause 4 waived by the maintainer, ruling 16 of 2026-09-28).
  - **`sigma=` is refused, naming `volatility=`, where it meant the volatility.** The functions: `build_diffusion_matrix`, `build_diffusion_matrix_1d`, `build_diffusion_matrix_2d` and `build_diffusion_matrix_from_geometry`, `DiffusionOperator.from_volatility`, `VariationalMFGProblem`, `create_quadratic_variational_mfg`, `create_obstacle_variational_mfg`, `diffusion_from_volatility`, `diffusion_from_volatility_torch`, `check_adi_compatibility`, and the strict-adjoint step `solve_fp_step_adjoint_mode` on FP-FDM and the weak-form FP solver. The manufactured-solution sources `hjb_source` and `fp_source` also refuse `sigma_kind=`, naming `volatility_kind=`. The refusal goes at v0.25.0, and the deprecation audit lists it.
  - **The internal helpers are renamed too, without a refusal**, because they sit on assembly paths called once per row: the FP-FDM stencil and boundary-row builders, the time-stepping steps, the HJB residual and Jacobian assemblers, the semi-Lagrangian and ADI diffusion steps, the Brownian increments and the Crank–Nicolson helpers. A stale `sigma=` there raises Python's own `TypeError`.
  - **Renamed attributes, fields and keys.**
    - `VariationalMFGProblem.sigma` and `HamiltonianValues.sigma` are now `.volatility`. Reading `.sigma` raises an `AttributeError` naming the replacement.
    - `MFGGridConfig.sigma` is now `volatility`, and `MFGArrays.get_solution_statistics()` reports it under `"volatility"` where it reported `"sigma"`; `ExperimentConfig.to_notebook_metadata()` returns that dictionary under `"solution_statistics"`. `MFGGridConfig(sigma=...)` is refused with an error naming `volatility=`. `extra="forbid"` rejected it already; the refusal only names the replacement.
    - `OperatorConfig.sigma`, exported from `alg.numerical.adjoint`, is now `OperatorConfig.volatility`.
    - The boundary-provider state that `FixedPointIterator` builds carries the volatility under `"volatility"`, where it was `"sigma"`. A provider of your own that read `state["sigma"]` now finds nothing there.
    - `save_experiment_data` writes `"volatility"` where it wrote `"sigma"`. Files saved before this carry the old key.
  - **The strict-adjoint FP step reads the volatility by its declared kind.** It used to refuse the problem's tensor by checking `is problem.volatility`, so an equal tensor passed as an override was read as a per-point field. That was the last identity check from part 2a.
    - It now follows part 2a's rule for every override, so two inputs it accepted before are refused: an array with no `volatility_kind=`, and a negative scalar.
    - `BlockIterator` calls it with `volatility=` and `volatility_kind=`, so an FP solver of your own used in adjoint mode must accept both keywords. The `AdjointCapableFPSolver` protocol now spells the signature the two implementations have: `volatility`, `time`, `volatility_kind`.
  - **Docs.** Twenty parameter docstrings called this `sigma` a "Diffusion coefficient"; they now say it is the SDE volatility, with D = σ²/2. So do `OperatorConfig`'s field, the notebook reporter's label, two unread `jax_utils` parameters and the comments on `base_hjb`'s `sigma_at_n`, which had called it the diffusion. Two user guides passed σ as `diffusion=` or labelled it a diffusion, and `AGENTS.md`'s boundary-condition example uses `volatility=`.
  - **Still spelt `sigma`, and not the agents' volatility:** the common-noise processes' own volatility, the Lévy jump width, and the maze Gaussian blur width. A test pins that list.
  - **The refusal decorators return the function they wrap, typed as itself.** Part 2a's `retired_volatility_keywords` was untyped, so mypy read each function it decorated as `Any` and stopped checking the calls to it. That hid 21 errors in `alg`, and part 2a recorded their disappearance as an improvement: the real count went from 762 to 758, not to 737. With the decorators typed, `alg` is at 758, and this part adds no errors.
  - **What to change in your code:** `sigma=` → `volatility=`, `sigma_kind=` → `volatility_kind=`, `.sigma` → `.volatility`, and `state["sigma"]` → `state["volatility"]`. An array passed to `solve_fp_step_adjoint_mode` also needs `volatility_kind=`.

  Measured against `494dc7d4`: the part 1 solve oracle (123 fixtures) and the part 2a override oracle (33 fixtures) are unchanged bit for bit. Pins: `tests/unit/test_utils/test_sigma_names_no_volatility_2378.py`, each checked against a mutation that reverts its fix. The single-source ratchet's `D = sigma^2/2` pattern now matches `volatility` as well. It keys on the name, so the rename had left it blind. It finds the same 13 sites as before.
