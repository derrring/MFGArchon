  - The section ended `Ref: DEPRECATION_LIFECYCLE_POLICY.md`. That file existed as `docs/development/DEPRECATION_LIFECYCLE_POLICY.md` until `cc21745c` (#852, "Move internal dev notes to mfg-research, keep user docs") moved it out. The pointer has named nothing in this repository since, in the file every contributor reads first, for the one policy a removal batch is measured against.
  - **The four inline clauses are the whole of the policy as this repository holds it**, so the fix is to say that rather than point somewhere a reader cannot follow.
  - **The `Ref:` named the right artifact all along; only its path died.** `a6569f57` added that very file as a 596-line document, and the #616 post-mortem is its body — so the origin is cited from this repository's own history, where any reader can run `git show`: #490 redirected `conservative=` to `advection_scheme`, kept the old parameter with a deprecation warning, and set the new default to `gradient_upwind`, which leaks mass at the boundary. Callers relying on the correct default since #382 silently got the broken one for **34 days** at a **99.4%** mass error. The post-mortem's own verdict is *"Deprecated with warning but wrong default → 1 month of catastrophic bugs"* and *"**Equivalence test requirement** would have caught the wrong default immediately"* — quoted with its markdown, since the bold splits the literal and a plain grep for the sentence returns zero, the same way a line break hid `status of the NEGATION` in `gate_hook.sh` from two separate searches today — which is precisely why clause (1) demands zero behaviour difference and clause (2) makes the equivalence test mandatory. `c18c798d` removed the parameter.
  - **A first draft of this said "there is no `conservative=` parameter".** That was true of #616's issue *body* and false of the repository: `git log -S'conservative'` finds both the introduction and `c18c798d`'s removal. A negative existence claim read off a single artifact is the wrong instrument — the symptom was in the issue, the cause was in history.
  - Struck in place rather than deleted, because a reader who has seen the old `Ref:` needs to learn that the file moved rather than that it was never there.
