- **A problem's volatility is held as supplied, and `sigma` is retired** (#2375 ruling 6, #2378 phase 4 part 1, fixes #2376). **This breaks code that passes `sigma=` or reads `problem.sigma`.**
  - **What changed.**
    - `MFGProblem(sigma=...)` and `Model(sigma=...)` raise `TypeError`, naming the replacement. Pass `volatility=`, the SDE volatility Σ; `diffusion=`, the PDE coefficient A = ½ΣΣᵀ, is still accepted, and giving both raises. `StochasticMFGProblem` and `MultiPopulationMFGProblem` take `volatility=` too.
    - An array volatility (or an array `diffusion=`) must say how it is read: `volatility_kind="field"` (isotropic per point) or `"tensor"` (trailing `(d, k)` noise matrix, constant or per grid point). A `(d, d)` tensor and a d×d field have the same shape, and the library does not guess. A kind given with a scalar, and a tensor on a 1-D problem, are refused.
    - `problem.volatility` is Σ as supplied -- scalar, array or callable -- and `problem.diffusion` is A, derived by `diffusion_from_volatility`. Both names existed before with a scalar meaning; they no longer collapse anything.
    - `problem.sigma`, `problem.volatility_field` and `problem.diffusion_field` raise `AttributeError`, naming the replacement.
    - A tensor volatility now has a constructor route: `MFGProblem(volatility=S, volatility_kind="tensor")`. `HJBSemiLagrangianSolver` discretises its cross term (#2198); solvers that cannot read a tensor refuse it (GFDM, FVM, WENO) or warn as before (HJB-FDM, a non-diagonal Σ).
  - **Fixed (#2376).** An array volatility was reduced to its mean, and a callable one replaced by the literal `1.0`, for every reader of `problem.sigma` -- among them the paired-solver check, the adjoint-consistent BC state, the weak-form and strict-adjoint diffusion, the GFDM pre-solve fallback, and `StochasticMFGProblem`'s conditional problems. There is no such scalar any more. A consumer that can use only one scalar calls `scalar_volatility(volatility, consumer=...)`, which refuses an array or a callable by name. On a scalar volatility nothing changes: measured against `0f937601`, 15 solve fixtures -- FDM, FVM, SL, particle, WENO, three 2-D schemes, `diffusion=` input and the v1.0 API -- are bit-identical, as are 9 field and callable fixtures on the paths that read the field.
  - **Also refused now.** Distinct per-population volatilities on `MultiPopulationMFGProblem`: no solver reads a population's own, so every population was solved at population 0's.
  - **Removed.** `scalar_diffusion_from_volatility` (its array arm averaged a field with a warning), and FP-FDM's deprecated, uncalled `_solve_fp_1d` / `_solve_fp_1d_with_callable`.
  - **Not in this change.** Solver-method parameters named `volatility_field=` and internal `sigma=` parameters keep their names until part 2; routing every assembled operator through one converter is part 3.
  - **What to change in your code.** `sigma=` → `volatility=`; add `volatility_kind="field"` to an array volatility; read `problem.volatility` for Σ and `problem.diffusion` for A.
