- **A problem's volatility is held as supplied, and `sigma` is retired** (#2375 ruling 6, #2378 phase 4 part 1, fixes #2376). **This breaks code that passes `sigma=` or reads `problem.sigma`.**
  - **What changed.**
    - `MFGProblem(sigma=...)` and `Model(sigma=...)` raise `TypeError`, naming the replacement, and reading `Model.sigma` raises `AttributeError`. Pass `volatility=`, the SDE volatility Σ; `diffusion=`, the PDE coefficient A = ½ΣΣᵀ, is still accepted, and giving both raises. `StochasticMFGProblem` and `MultiPopulationMFGProblem` take `volatility=` too; on the latter, `sigma_vec` and `get_sigma_k` are now `volatility_vec` and `get_volatility_k`.
    - An array volatility (or an array `diffusion=`) must say how it is read: `volatility_kind="field"` (isotropic per point) or `"tensor"` (trailing `(d, k)` noise matrix, constant or per grid point). A `(d, d)` tensor and a d×d field have the same shape, and the library does not guess. A kind given with a scalar, a tensor on a 1-D problem, and a tensor with k ≠ d noise sources are refused -- no solver reads a non-square Σ yet, and the message names the symmetric `(d, d)` square root with the same A. A list is held as a float array and validated like one.
    - A callable's array output is read per point unless `volatility_kind="tensor"` says otherwise -- how every solver that evaluates a callable volatility reads it, and what a callable `diffusion=` returning an array relied on. Where the problem converts the output itself -- `problem.diffusion`, and a `diffusion=` callable -- an output with trailing `(d, d)` axes that is not one value per evaluation point (a constant or per-point tensor) is refused unless the kind is declared, as is one from a d×d grid's own points, where the two readings coincide; a 3-D grid shaped `(Nx, 3, 3)` returns one value per point and is read per point. A solver evaluating a kind-less `volatility=` callable does not make that check: FP-FDM and HJB-FDM read the output per point, so on a 2×2 grid they cannot tell a `(2, 2)` tensor from a field. Declare `volatility_kind="tensor"` for a tensor-valued callable.
    - `problem.volatility` is Σ as supplied -- scalar, array or callable -- and `problem.diffusion` is A, derived by `diffusion_from_volatility`. Both names existed before with a scalar meaning; they no longer collapse anything. `get_problem_info()["coefficients"]` carries `"volatility"` where it carried `"sigma"`.
    - `problem.sigma`, `problem.volatility_field` and `problem.diffusion_field` raise `AttributeError`, naming the replacement.
    - A solver's `None` volatility default is the problem's own volatility. `HJBFDMSolver`, `FPFDMSolver` and the particle callable-drift path read the problem's volatility by its declared kind, whether it arrives as `None` or as the object `MFGProblem.solve()` forwards; any other per-solve override -- a distinct object, even an equal one -- is still read by shape until part 2 gives overrides a kind.
    - A tensor volatility now has a constructor route: `MFGProblem(volatility=S, volatility_kind="tensor")`. `HJBSemiLagrangianSolver` discretises its cross term (#2198), and `FPFDMSolver` assembles A = ½ΣΣᵀ. Solvers that cannot read a tensor refuse it by name: GFDM, FVM, WENO, FP-FDM's strict-adjoint step, and `HJBFDMSolver` for anything but a constant diagonal Σ -- its axis weights are σᵢᵢ²/2 with no cross term, which for a non-diagonal Σ is not A even on the diagonal. Passed as an explicit override, HJB-FDM still only warns, and the warning now says so.
  - **Fixed (#2376).** An array volatility was reduced to its mean, and a callable one replaced by the literal `1.0`, for every reader of `problem.sigma` -- among them the paired-solver check, the adjoint-consistent BC state, the weak-form and strict-adjoint diffusion, the GFDM pre-solve fallback, and `StochasticMFGProblem`'s conditional problems. There is no such scalar any more. A consumer that can use only one scalar calls `scalar_volatility(volatility, consumer=...)`, which refuses an array or a callable by name. On a scalar volatility nothing changes: measured against `0f937601`, 30 scalar solve fixtures are bit-identical -- FDM, FVM, SL, particle, WENO and GFDM pairs, three 2-D schemes, `diffusion=` input and the v1.0 API, reached through `MFGProblem.solve()` and through a `FixedPointIterator` or `BlockGaussSeidelIterator` built directly, which leaves each solver to its own `None` default. So are 18 field and callable fixtures on the FDM, constant-field FVM and GFDM (with and without LLF) paths; where a pair solved at the collapsed value, it now refuses by name.
  - **Also fixed.** HJB-FDM crashed on every 2-D field volatility (a grid-shaped D times a flattened Laplacian). `save_experiment_data` recorded the collapsed scalar, in its parameters and its file name: `1.0` for a callable, the mean for an array. It now records an array as supplied with its kind, tagging the file name by that kind, and a callable -- which `np.savez` cannot pickle -- as the tag `"callable"`.
  - **Also refused now.**
    - `FPParticleSolver`'s grid-drift path (an ndarray drift, the path a coupled solve takes) with an array volatility: it consumes one scalar and averaged the field, with a warning (#1248). A callable drift, or `drift_field=None`, reads the volatility per particle.
    - Distinct per-population volatilities on `MultiPopulationMFGProblem`: no solver reads a population's own, so every population was solved at population 0's.
    - A paired HJB / FP solver whose problems hold one callable and one scalar or array volatility: they cannot be shown equal without evaluating the callable, and before this change the pair was refused only because the callable read as `1.0`. Two callables are not compared: any two pass, distinct or not, as before (the guard cannot evaluate them, and a test double is callable, #1489), so with a callable volatility build both solvers from one problem. Arrays compare by content and kind, so a scalar and a constant field equal to it are now one problem, while the same entries under the other kind -- an all-equal tensor, whose A = ½ΣΣᵀ is not σ²/2·I -- are not.
  - **Removed.** `scalar_diffusion_from_volatility` (its array arm averaged a field with a warning), and FP-FDM's deprecated, uncalled `_solve_fp_1d` / `_solve_fp_1d_with_callable`.
  - **Not in this change.** Solver-method parameters named `volatility_field=` and internal `sigma=` parameters keep their names until part 2 (part 2a, in this release, renames the first: `2378-volatility-override-read-by-kind.changed.md`); routing every assembled operator through one converter is part 3.
  - **What to change in your code.** `sigma=` → `volatility=`; add `volatility_kind="field"` to an array volatility; read `problem.volatility` for Σ and `problem.diffusion` for A.
