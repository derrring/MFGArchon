- **The `x` the library builds for a body has one owner** (#2875). Every door that builds the `x` it hands a body from the library's own points builds it in `types/callable_protocols.py`: through `coordinate_tuple`, which gains `shape=` (the shape each entry is given), `point_tuple`, `point_at`, or one of two new functions there, `grid_coordinates` for the points of a tensor grid and `line_coordinates` for points on a line.
  - **The doors that built `x` themselves:** FEM's quadrature points, FVM's faces and its periodic seam, FP-FDM's volatility tensor, the grid a coefficient or a solver's drift is read on (`points_of`), the points HJB refuses as non-finite, a problem source at the density's shape, a boundary value's point, the construction check's probe points, the 1-D Nitsche and adaptive-mesh doors, a Lagrangian's stand-in point in `proximal`, and the 1-D variational and optimal-transport doors. Each hands the same coordinates as before, as a tuple.
  - **Two entries change type.** The point at which the construction check reads a boundary value at a wall node holds numpy floats where it held Python floats, and FVM's periodic seam at $d = 1$ hands its point as a numpy float where it handed a 0-d array.
  - **The network solvers** still hand a node as `np.array([i])`. The form of `x` on a network is #3012's.
