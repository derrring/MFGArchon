- **`MFGComponents` takes a Hamiltonian or a Lagrangian, not both, and a Lagrangian-defined one keeps its derived Hamiltonian private** (#2901).
  - **Both together are refused,** with `Model`'s rule: "Provide hamiltonian OR lagrangian, not both. They are dual descriptions of the same game". Before, both were used as given. Every reader but HJB-SL's DPP path read the Hamiltonian, the DPP path read the Lagrangian, and nothing compared them.
  - **The public field changes.** After `MFGComponents(lagrangian=L)`, `components.hamiltonian` is now `None`, the field as the user gave it, where it used to be the Hamiltonian derived from `L`. Read the derived Hamiltonian through `MFGProblem.hamiltonian_class`. MFGComponents has no public accessor of its own for it.
  - **The reason:** a copy of the components (`dataclasses.replace`) now carries one description. With the derived Hamiltonian in the public field, a copy would hand both to the constructor and be refused.
