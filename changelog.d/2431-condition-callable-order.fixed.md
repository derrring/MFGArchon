- **A time-first `u_terminal` or `m_initial` is read correctly, and the old order is refused (#2431).** `Conditions(u_terminal=lambda t, x: x**2)` used to give a terminal condition identically $T^2$, with no warning: the IC/BC adapter probed `f(x, t)` before `f(t, x)`, and both return a number. A callable that needs more than `x` is now bound by its parameter names through `bind_user_callable`, like every other user callable since #2378 phase 5. `lambda t, x` is read at $T$ for `u_terminal` and $0$ for `m_initial`. `lambda x, t` is refused, naming the order, as is a 1-D two-argument callable whose names do not say which argument is time (`lambda a, b`), and an `np.vectorize` object. In 2-D and 3-D a callable that names no time parameter is read as the deprecated expanded coordinates `f(x, y)` / `f(x, y, z)`, with their warning. Before, such a callable was first probed as `f(x, t)` and `f(t, x)`. Space-only callables are read as before. `CallableSignature.SPATIOTEMPORAL_XT` is removed, since nothing returns it.
